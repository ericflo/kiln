# Hypothesis: h1-r16-6ep

## Family
H1 — proven recipe, first ablation.

## Claim
Proven recipe (rank=16, alpha=32, lr=1e-4, 6 epochs, samples_per_prompt=1,
max_tokens=384, top_k=8) will lift `required_fields` by ≥4pp
(0.7000 → ≥0.7400) and composite by ≥2pp (0.8509 → ≥0.8709). This is a
structured-output capability — same family as code-symbol-extraction
(capability #2, 97% skip rate) — but with max_tokens=384 well over the
~60-80 token natural response length, so per capability #3's lesson
OPD should have rollout budget room to move content rather than format.

## Mechanism
The 4B's failure mode is dropping required fields. At rollout positions
where the student emits `"}"` (closing the JSON) too early, the teacher's
top-K distribution will have higher mass on the remaining required-field
key tokens (`"path"`, `"command"`, etc.). Reverse-KL pulls the student
toward including them. parses and type_correctness are already saturated;
required_fields headroom is 80% of total movable.

## Configuration
- prompts: prompts/h1-r16-6ep.jsonl (26 tool-call prompts, 12 tool shapes)
- rank: 16  alpha: 32  lr: 1e-4
- epochs: 6  samples_per_prompt: 1  max_tokens: 384  top_k: 8
- env: KILN_STREAMING_PREFILL=1
- teacher_extra_messages: NONE (symmetric — iter 2 will test H9 asymmetric)

## What's held constant from previous iteration
N/A — first OPD iter for this capability. Hyperparameters mirror the
"recipe that worked" from capability #3 iter 2 (the only OPD adapter so
far where the target sub-score actually moved).

## Falsification plan
- If `required_fields` Δ < +1pp AND skip_rate > 90%: structured-output
  skip-rate issue persists even at max_tokens=384. Pivot to iter 2 = H9
  (asymmetric teacher prompts) — sharp teacher distributions reduce
  skips indirectly. This is what kiln's new asymmetric-prompt feature
  is for.
- If `required_fields` Δ ≥ +4pp: claim confirmed. Iter 2 = H9 anyway
  (test if asymmetric prompts push it further).
- If composite < 0.5 × baseline (< 0.425): all-zeros gate fires;
  treat as broken adapter, write failure_mode.md.

## Inspection plan
Sample 3 non-eval responses on prompts where the base model dropped
required fields. Check that the JSON parses, contains all required
fields, has correct types, no extras.

---

## Verdict
✓ Confirmed — required_fields +16.67pp (0.700 → 0.867, claim was ≥+4pp).
Composite +4.30pp (0.8509 → 0.8939) vs claim ≥+2pp. This is the
LARGEST single-iter target sub-score lift across all 4 capabilities
(cap #3 iter 2 was +3.46pp on entity_recall; this is ~5x that).

10 effective / 156 nominal = 93.6% skip rate — better than capability
#2's 97% but still high. The max_tokens=384 widening from the #3
lesson did NOT eliminate the structural skip issue on
structured-output tasks; it shaves a few points but the floor remains.

Sub-scores:
- parses: 1.000 → 0.933 (-6.67pp, minor regression on saturated)
- required_fields: 0.700 → 0.867 (+16.67pp, TARGET MOVED HARD)
- type_correctness: 0.989 → 0.933 (-5.56pp, minor regression on saturated)
- no_extra_fields: 0.871 → 0.869 (essentially flat)

Inspection (3 non-eval responses):
- delete_file: perfect
- list_files: produced {"files":["..."]} — model emitted what looks like
  a tool RESULT rather than a CALL. Shape entirely wrong; this is what
  drives the parses+type_correctness regressions.
- run_bash: perfect

The adapter learned "include more keys" — great for required_fields,
but it sometimes overshoots into producing tool-result-shaped JSON or
mistyping fields. Two regressions on saturated sub-scores are minor in
weighted terms (-0.67pp from parses, -1.67pp from type_correctness)
vs the +6.67pp gain on weighted required_fields.

Next: Iter 2 = **H9 asymmetric teacher conditioning** — give the
teacher a small set of pristine tool-call exemplars in
`teacher_extra_messages` (visible only to the teacher). This is the
first real user of the kiln feature I just shipped. Two goals:
1. Sharpen teacher distribution on tool-call-shape tokens → recover
   the parses+type_correctness regressions while keeping required_fields up.
2. Test whether asymmetric prompts reduce the persistent skip rate
   floor on structured-output capabilities.
