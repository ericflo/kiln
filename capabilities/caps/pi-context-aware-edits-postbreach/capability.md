# Capability: pi-context-aware-edits-postbreach

**Status:** Postbreach restart for `pi-context-aware-edits`.

## Description

Before editing a file, the agent must read enough surrounding context to make
the edit stylistically and structurally consistent: imports, neighboring
functions, naming conventions, type-annotation style, comment style, logging
style, and error-handling pattern.

This restart exists because the original `pi-context-aware-edits` held-out eval
pool was exposed after H5 had already been trained and evaluated. All new
adapter-design work must use this fresh task pool and keep its eval files blind.

## Base Model

Qwen3.5-4B served locally by Kiln on `http://localhost:8420`.

## Rollout Source

Pi sessions. Multi-turn. Thinking stays enabled by the server default because
prior evidence shows thinking improves scores; efficiency is tracked through
tool-call and thinking-character aggregate metrics.

## Task Shape

Each task is a small workspace plus one edit request. The train/eval/hard-eval
splits are generated by `build_corpus.py` from templates spanning available
Python, Rust, and JavaScript toolchains. The oracle may read held-out task files;
the experimenter must not.

## Rubric (v0)

The rubric is inherited from the prebreach cap with JavaScript convention
checks added. Composite remains:

`outcome * format_compliance * (0.40*convention_consistency + 0.20*read_before_edit + 0.15*no_redundant_imports + 0.10*no_style_drift + 0.15)`

Tracked sub-scores:

- `outcome`: verifier command passed after the edit.
- `format_compliance`: final answer names the modified file and a preserved convention.
- `convention_consistency`: edit follows expected naming, typing, logging, error, and comment style.
- `read_before_edit`: target file was read before write/edit.
- `no_redundant_imports`: no obvious duplicate import pattern.
- `no_style_drift`: adjacent file style was preserved.

## Adversarial Design (§0)

**Q: Always read then ignore style.** Mitigation: `convention_consistency`
punishes wrong naming, typing, logging, error, and comment choices.

**Q: Emit the final sentence without editing.** Mitigation: `outcome` gates the
entire composite and requires the verifier to pass.

**Q: Copy an existing function body with the wrong semantics.** Mitigation:
task-specific verifier commands check the new callable or compile target.

**Q: Learn one constant convention.** Mitigation: the postbreach split spans
strict typed Python, loose camelCase Python, Rust Result style when available,
and JavaScript camelCase/CommonJS style when available.

## Baseline + Headroom

- Corpus generated 2026-05-24: 32 train / 16 eval / 12 hard-eval tasks across
  `py_strict_typed_snake`, `py_camel_loose`, `rust_snake_result`, and
  `js_camel_warn_jsdoc`.
- Rubric sanity passed: good min 0.9500, bad max 0.3667, separation +0.5833.
- Fresh held-out baseline (`postbreach-baseline-0`, thinking on, Pi output cap
  1024): **0.2996 ± 0.4497** over 16 tasks × 3 rollouts.
- Sub-scores: `outcome=0.5000`, `format_compliance=0.5625`,
  `convention_consistency=0.9736`, `read_before_edit=1.0000`,
  `no_redundant_imports=1.0000`, `no_style_drift=1.0000`.
- Headroom is concentrated in `outcome` (~52%) and `format_compliance` (~45%).
- Efficiency baseline: 5.46 tool calls/rollout, 1694.9 thinking chars,
  308.8 thinking chars/tool call.
- Method router note: composite is just below the strictness threshold
  (`0.2996 < 0.3`), so audit several **train** rollouts before training to
  verify that the rubric is rejecting true failures, not reasonable attempts.

## Hypotheses

- **PB-H1: fresh mixed-language baseline.** Measure the fresh postbreach pool
  before designing any new adapter. Expected: baseline remains midrange with
  headroom concentrated in `outcome` and `format_compliance`, but the
  JavaScript/Rust profiles should expose whether the earlier Python/Rust-only
  data was too narrow.
  - Result: kept as baseline. Composite is 0.2996 with outcome and format as
    the only material headroom. Proceed to train-rollout rubric audit before
    selecting the first postbreach adapter recipe.
- **PB-H2: oscillating SFT/GRPO chain.** If baseline reproduces the old
  outcome/format tradeoff, test the `pi-faithful-completion` lesson: alternate
  small outcome-focused ideal traces with final-format contrastive groups
  rather than training either distribution alone.
- **PB-H1: verifier-backed ideal trace SFT.** Because the fresh baseline is
  just below the router threshold and a train-rollout audit found true outcome
  and missing-final-response failures, first bootstrap the complete
  read/edit/verify/final rhythm from train-only ideal traces across all
  profiles.
  - Result: rejected. The 32-example, train-only, verifier-backed SFT arm
    trained and verified locally (`rank=4`, `alpha=8`, `lr=5e-6`, peak VRAM
    17,399 MiB), but blind 3-seed eval regressed composite to 0.1954
    (`delta=-0.1042`). Outcome rose only slightly (0.5000 to 0.5417), while
    `format_compliance` fell to 0.4583, `convention_consistency` fell to
    0.9306, and efficiency worsened (5.46 to 5.85 tool calls; 1694.9 to
    1840.8 thinking chars). Single-distribution ideal trace SFT repeats the
    prebreach H4 failure mode.
- **PB-H2: train-rollout agentic GRPO + light ECHO.** Because synthetic SFT
  hurt format and efficiency, collect train-only Pi rollouts and train a small
  distribution-matched GRPO arm (`rank=4`, `alpha=8`, `lr=5e-6`,
  `echo_lambda=0.02`) on reward-varied groups.
  - Result: rejected. The clean base train collection had enough reward
    variance (10/16 groups survived `--filter-var-min=0.05`) and the adapter
    trained and verified with gradient checkpointing, but blind eval was flat:
    0.2994 vs. 0.2996 baseline (`delta=-0.0001`). Outcome rose slightly
    (0.5000 to 0.5208), while `format_compliance` fell from 0.5625 to 0.5104.
    Low-rank, low-lambda GRPO moved the edit-completion signal a little but did
    not protect the final-response contract.
- **PB-H3: light terminal-state prompt + stronger Agentic GRPO/ECHO.** Apply
  the `pi-faithful-completion` lesson that a light explicit prompt plus
  stronger GRPO hyperparameters can move terminal behavior: collect fresh
  train-only rollouts with the stricter read/edit/verify/final prompt, then
  train `rank=16`, `alpha=32`, `lr=3e-5`, `echo_lambda=0.05` if reward
  variance remains usable. This targets outcome without letting final format
  regress.
  - Result: rejected. The prompt/hyperparameter combo trained and verified,
    but blind eval regressed to 0.2458 (`delta=-0.0538`). It did move
    `format_compliance` upward (0.5625 to 0.6042), but collapsed `outcome`
    from 0.5000 to 0.4375. The strict workflow prompt is too outcome-hostile
    for this cap, even though it teaches the terminal sentence.
- **PB-H4: default-prompt strong Agentic GRPO/ECHO.** Reuse the clean PB-H2
  default-prompt train rollout distribution, but apply the stronger
  `pi-faithful-completion` hyperparameters from PB-H3 (`rank=16`, `alpha=32`,
  `lr=3e-5`, `echo_lambda=0.05`). This isolates whether PB-H2 failed because
  the update was too weak, while avoiding PB-H3's strict-prompt outcome
  damage.
  - Result: rejected. The stronger default-prompt recipe trained and verified
    with gradient checkpointing, but blind eval was 0.2900 (`delta=-0.0096`).
    It improved `format_compliance` substantially (0.5625 to 0.6875) and cut
    efficiency cost (4.94 tool calls, 1449.8 thinking chars), but `outcome`
    fell to 0.3750 and `convention_consistency` fell to 0.9125. Strong GRPO
    on the PB-H2 rollout distribution over-optimizes terminal shape at the
    expense of correct edits.
- **PB-H5: default-prompt moderate Agentic GRPO/ECHO.** Reuse the clean PB-H2
  default-prompt train rollout distribution with an intermediate update
  (`rank=8`, `alpha=16`, `lr=1e-5`, `echo_lambda=0.03`). This tests whether
  the useful H2 outcome movement and H4 format movement can be balanced without
  the H4 outcome/convention collapse.
  - Result: rejected. The moderate update trained and verified, and blind eval
    preserved the PB-H2 outcome lift (`outcome=0.5208`) while improving format
    (`format_compliance=0.6458`). Composite still fell to 0.2683
    (`delta=-0.0312`) because `convention_consistency` fell to 0.9417,
    `read_before_edit` and `no_style_drift` slipped to 0.9792, and zero-score
    rollouts increased to 34/48. Intermediate GRPO balances outcome and format
    better than H4, but still fails to preserve the full edit contract.
- **PB-H6: train-winner trajectory SFT.** Extract train-only successful Pi
  trajectories from the clean PB-H2 rollout data (reward >= 0.95; 17
  completions across 11 groups) and imitate those full successful trajectories
  with a small SFT update. This tests whether distribution-matched successful
  traces can preserve outcome, format, and convention better than synthetic
  ideal SFT or reward-only GRPO.

## Standard Workflow

```bash
python3 build_corpus.py
python3 rubric_sanity.py
SEEDS=3 OUT_FILE=/tmp/pi-context-aware-edits-postbreach-baseline.json ./capability.oracle.sh
```

## Kiln Features Used

- `kiln serve` with CUDA 13.2 on RTX 4090.
- `cuda_sft_file` for curated SFT stages.
- `cuda_grpo_ablation` with explicit gradient checkpointing for GRPO stages.
- `kiln adapters verify` after each trained adapter.
