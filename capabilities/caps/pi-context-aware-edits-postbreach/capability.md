# Capability: pi-context-aware-edits-postbreach

**Status:** Postbreach restart for `pi-context-aware-edits`.

## Description

Before editing a file, the agent must read enough surrounding context to make
the edit stylistically and structurally consistent: imports, neighboring
functions, naming conventions, type-annotation style, comment style, logging
style, and error-handling pattern.

This restart exists because the original `pi-context-aware-edits` held-out eval
pool was exposed after H5 had already been trained and evaluated. All new
adapter-design work must use this fresh task pool and keep its eval files blind.

## Base Model

Qwen3.5-4B served locally by Kiln on `http://localhost:8420`.

## Rollout Source

Pi sessions. Multi-turn. Thinking stays enabled by the server default because
prior evidence shows thinking improves scores; efficiency is tracked through
tool-call and thinking-character aggregate metrics.

## Task Shape

Each task is a small workspace plus one edit request. The train/eval/hard-eval
splits are generated by `build_corpus.py` from templates spanning available
Python, Rust, and JavaScript toolchains. The oracle may read held-out task files;
the experimenter must not.

## Rubric (v0)

The rubric is inherited from the prebreach cap with JavaScript convention
checks added. Composite remains:

`outcome * format_compliance * (0.40*convention_consistency + 0.20*read_before_edit + 0.15*no_redundant_imports + 0.10*no_style_drift + 0.15)`

Tracked sub-scores:

- `outcome`: verifier command passed after the edit.
- `format_compliance`: final answer names the modified file and a preserved convention.
- `convention_consistency`: edit follows expected naming, typing, logging, error, and comment style.
- `read_before_edit`: target file was read before write/edit.
- `no_redundant_imports`: no obvious duplicate import pattern.
- `no_style_drift`: adjacent file style was preserved.

## Adversarial Design (§0)

**Q: Always read then ignore style.** Mitigation: `convention_consistency`
punishes wrong naming, typing, logging, error, and comment choices.

**Q: Emit the final sentence without editing.** Mitigation: `outcome` gates the
entire composite and requires the verifier to pass.

**Q: Copy an existing function body with the wrong semantics.** Mitigation:
task-specific verifier commands check the new callable or compile target.

**Q: Learn one constant convention.** Mitigation: the postbreach split spans
strict typed Python, loose camelCase Python, Rust Result style when available,
and JavaScript camelCase/CommonJS style when available.

## Baseline + Headroom

- Corpus generated 2026-05-24: 32 train / 16 eval / 12 hard-eval tasks across
  `py_strict_typed_snake`, `py_camel_loose`, `rust_snake_result`, and
  `js_camel_warn_jsdoc`.
- Rubric sanity passed: good min 0.9500, bad max 0.3667, separation +0.5833.
- Fresh held-out baseline (`postbreach-baseline-0`, thinking on, Pi output cap
  1024): **0.2996 ± 0.4497** over 16 tasks × 3 rollouts.
- Sub-scores: `outcome=0.5000`, `format_compliance=0.5625`,
  `convention_consistency=0.9736`, `read_before_edit=1.0000`,
  `no_redundant_imports=1.0000`, `no_style_drift=1.0000`.
- Headroom is concentrated in `outcome` (~52%) and `format_compliance` (~45%).
- Efficiency baseline: 5.46 tool calls/rollout, 1694.9 thinking chars,
  308.8 thinking chars/tool call.
- Method router note: composite is just below the strictness threshold
  (`0.2996 < 0.3`), so audit several **train** rollouts before training to
  verify that the rubric is rejecting true failures, not reasonable attempts.

## Hypotheses

- **PB-H1: fresh mixed-language baseline.** Measure the fresh postbreach pool
  before designing any new adapter. Expected: baseline remains midrange with
  headroom concentrated in `outcome` and `format_compliance`, but the
  JavaScript/Rust profiles should expose whether the earlier Python/Rust-only
  data was too narrow.
  - Result: kept as baseline. Composite is 0.2996 with outcome and format as
    the only material headroom. Proceed to train-rollout rubric audit before
    selecting the first postbreach adapter recipe.
- **PB-H2: oscillating SFT/GRPO chain.** If baseline reproduces the old
  outcome/format tradeoff, test the `pi-faithful-completion` lesson: alternate
  small outcome-focused ideal traces with final-format contrastive groups
  rather than training either distribution alone.
