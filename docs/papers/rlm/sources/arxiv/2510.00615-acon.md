###### Abstract

Large language models (LLMs) are increasingly deployed as agents in dynamic, real-world environments, where success requires both reasoning and effective tool use. A central challenge for agentic tasks is the growing context length, as agents must accumulate long histories of actions and observations.
This expansion raises costs and reduces efficiency in long-horizon tasks, yet prior work on context compression has mostly focused on single-step tasks or narrow applications.
We introduce Agent Context Optimization (Acon), a unified framework that optimally compresses both environment observations and interaction histories into concise yet informative condensations.
Acon leverages compression guideline optimization in natural language space: given paired trajectories where full context succeeds but compressed context fails, capable LLMs analyze the causes of failure, and the compression guideline is updated accordingly.
Furthermore, we propose distilling the optimized LLM compressor into smaller models to reduce the overhead of the additional module.
Experiments on AppWorld, OfficeBench, and Multi-objective QA show that Acon reduces memory usage by 26-54% (peak tokens) while largely preserving task performance, preserves over 95% of accuracy when distilled into smaller compressors, and enhances smaller LMs as long-horizon agents with up to 46% performance improvement.
Our code is available at <https://github.com/microsoft/acon>.

## 1 Introduction

Large language models (LLMs) have become the backbone of AI agents across diverse real-world tasks, leveraging language knowledge and reasoning to plan, act, and adapt in dynamic environments (Yao et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib53)). These tasks often unfold over extended horizons: the agent must gather information, invoke tools, and revise plans based on feedback. In such settings, context is not auxiliary but foundational, as tool APIs and data formats lack standardization (Anthropic, [2024a](https://arxiv.org/html/2510.00615v2#bib.bib2)), and even personalized environments differ in file structures or account data. Agents must therefore accumulate and maintain records of prior actions, observations, and world state. Losing this information, such as an email identifier, file version, or API format, can derail task success.

![Refer to caption](x1.png)

Figure 1: Accuracy–Peak tokens trade-off on AppWorld (Trivedi et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib38)). We compare average accuracy versus peak input tokens in history compression. Acon (ours) reduces cost while preserving accuracy for the large model (gpt-4.1) relative to a naive prompting baseline, and even improves accuracy on smaller models (gpt-4.1-mini and Qwen-14B). More results are in [Section 4](https://arxiv.org/html/2510.00615v2#S4 "4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

The centrality of context, however, makes it a bottleneck. As interactions accumulate, contexts grow unbounded as in [Figure 2](https://arxiv.org/html/2510.00615v2#S1.F2 "Figure 2 ‣ 1 Introduction ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), creating two major challenges. First, the inference cost of transformers scales with the context length, which becomes prohibitive in long-horizon tasks. Second, excessively long contexts dilute relevant information, distracting the model with outdated or extraneous details (Shi et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib33)). These issues make effective context management and compression indispensable. Existing compression approaches only partially address this need. Dialogue-oriented systems rely on session-level summarization or tiered memories suitable for conversational coherence but inadequate for multi-step carry-over (Packer et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib27)). Document-centric methods in long-context QA or in-context learning (Li et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib21); Jiang et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib11)) assume single-step reasoning where context can be discarded after producing an answer. While effective in their domains, these strategies fall short for complex multi-step tasks where success depends on retaining structured signals across many interactions.

![Refer to caption](x2.png)

Figure 2: Motivation: Unbounded context in LLM agents. As LLM agents interact with environments, actions and observations continuously accumulate, leading to ever-growing contexts that incur high memory usage as in the red line on the right plot. This motivates *Agent Context Optimization* (Acon), which optimally compresses histories and observations into concise summaries, reducing peak tokens and memory as in the blue line on the right plot.

The challenge becomes particularly critical in productivity scenarios (e.g., email management, document processing, or workflow automation) where agents must coordinate across heterogeneous tools and maintain precise state information. Unlike simpler agent tasks, these environments demand preservation of diverse signal types: factual history, action–outcome relationships, evolving environment states, success preconditions, and future decision cues. Naive strategies like token truncation or generic summarization easily lose critical details essential for long-horizon reasoning. Recent agent-focused compression methods (Deng et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib7); Lee et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib20); Smith, [2025](https://arxiv.org/html/2510.00615v2#bib.bib35)) either specialize narrowly or rely on brittle heuristics, limiting their applicability across the full spectrum of multi-step agent tasks.

We address these challenges with Agent Context Optimization (Acon), a unified framework for systematic and adaptive context compression. Our study yields three key findings. First, task- and environment-specific guidelines enable consistent context compression across diverse agents without sacrificing performance. Second, optimized contexts not only reduce costs but also improve decision quality, allowing smaller LLMs to act more effectively. Third, high-quality compressors can be distilled into even smaller models, reducing overhead and improving deployability.

Acon dynamically condenses environment observations and interaction histories into concise, informative representations. Rather than handcrafting prompts, we introduce a guideline optimization pipeline that refines compressor prompts via failure analysis in natural language space (Pryzant et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib30); Khattab et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib14); Yüksekgönül et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib55); Han et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib8)), ensuring that critical environment-specific and task-relevant information is retained. Importantly, Acon is gradient-free, requiring no parameter updates, making it directly usable with closed-source or production models. We further distill optimized compressors into smaller models for cost-efficient deployment.

We validate Acon on three multi-step agent benchmarks: AppWorld (Trivedi et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib38)), OfficeBench (Wang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib42)), and Multi-objective QA (Kwiatkowski et al., [2019](https://arxiv.org/html/2510.00615v2#bib.bib18); Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58)), each requiring 15+ interaction steps. Our empirical results demonstrate clear advantages of Acon:
(i) lowers memory usage by 26–54% (peak tokens) while largely maintaining task performance;
(ii) enables effective distillation of the context compressor into smaller models, preserving 95% of the teacher’s accuracy across all benchmarks, thereby reducing the overhead of the additional module;
(iii) allows small LMs to function more effectively as agents, improving performance by 32% on AppWorld, 20% on OfficeBench, and 46% on Multi-objective QA by mitigating the distraction of long contexts through Acon.
Our result highlights on AppWorld benchmark are in [Figure 1](https://arxiv.org/html/2510.00615v2#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

To summarize, our work makes the following contributions:

- •

  We propose Agent Context Optimization (Acon), a framework for compressing both environment observations and interaction histories, tailored to multi-step, long-horizon agentic tasks.
- •

  We develop a failure-driven, task-aware compression guideline optimization. Our approach is entirely gradient-free and readily applicable to any LLMs, including API-based models.
- •

  We provide a cost-efficient solution by distilling optimized compressors into smaller models, preserving over 95% of the teacher’s performance while reducing module overhead.
- •

  We validate Acon on AppWorld, OfficeBench, and Multi-objective QA, showing that it reduces memory usage by 26-54% (peak tokens) while preserving task success with large LLMs, and enabling small LMs to achieve 20-46% performance improvements.

## 2 Related Works

#### Long-horizon LLM agents.

Large language model (LLM) agents extend pretrained models beyond static single-step reasoning tasks (e.g., RAG-based QA, math problem solving, or code generation) to interactive decision-making in dynamic environments (Yao et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib53); Wang et al., [2024a](https://arxiv.org/html/2510.00615v2#bib.bib41); Team et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib37); OpenAI, [2025a](https://arxiv.org/html/2510.00615v2#bib.bib23)).
Unlike chatbots or solvers that return an answer in one pass, agents must iteratively observe their surroundings, select tools, and execute actions while revising their plans based on feedback (Shridhar et al., [2021](https://arxiv.org/html/2510.00615v2#bib.bib34); Jimenez et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib12); Zhou et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib57); Wei et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib43); Xie et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib47); Bonatti et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib4)).
Recent work highlights the importance of *long-horizon LLM agents*, which tackle tasks that unfold over dozens to hundreds of steps and require coordination across multiple applications and tools (Kwa et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib17); Trivedi et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib38); Wang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib42); [2025b](https://arxiv.org/html/2510.00615v2#bib.bib40)).
A central challenge in these scenarios lies in managing the *dynamic long context*, where the agent must retain multi-step interaction histories and handle diverse observations produced by heterogeneous environments.

#### Context compression for LLMs.

Managing this ever-growing context has been a longstanding challenge, and a variety of approaches have been proposed to compress LLM inputs.
Prior works on context compression can be broadly grouped into three directions: document- or retrieval-based compression (Seo et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib31); Li et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib21); Xu et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib48); Yoon et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib54); Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58); Jiang et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib11); Shandilya et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib32)), dialogue memory summarization (Xu et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib49); Maharana et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib22); Wang et al., [2025a](https://arxiv.org/html/2510.00615v2#bib.bib39)), and low-level KV cache compression (Zhang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib56)). While each line of research has demonstrated benefits in its respective setting, they remain insufficient for the dynamic and heterogeneous contexts required by long-horizon agents.

Beyond these directions, a few recent studies have attempted to compress context specifically for LLM agents (Deng et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib7); Lee et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib20); Smith, [2025](https://arxiv.org/html/2510.00615v2#bib.bib35); Yang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib52)). However, these approaches either rely on naive prompting or target narrow domains such as the accessibility tree in web browsing, limiting their generality.
In contrast, our work introduces a universal *agent context optimization* framework that is applicable to arbitrary agents. It supports both history and observation compression, and incorporates a generalizable optimization methodology that is agnostic to the underlying model, making it applicable to both open-source and proprietary API-based LLMs.

## 3 Agent Context Optimization (Acon)

We present Agent Context Optimization (Acon), a unified framework for optimized history and observation compression in long-horizon LLM agents.
We begin by formulating the agent task and defining context cost in [Section 3.1](https://arxiv.org/html/2510.00615v2#S3.SS1 "3.1 Problem Formulation ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").
Next, in [Section 3.2](https://arxiv.org/html/2510.00615v2#S3.SS2 "3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), we introduce generative compression with LLMs for both history and observation, and formalize the associated optimization objective and its challenges.
We then propose our optimization method in [Section 3.3](https://arxiv.org/html/2510.00615v2#S3.SS3 "3.3 Optimizing Compression Guidelines ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), followed by a distillation that enables smaller models for compressions to improve efficiency ([Section 3.4](https://arxiv.org/html/2510.00615v2#S3.SS4 "3.4 Distilling Context Compression into Small Models ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")).

### 3.1 Problem Formulation

#### Task.

An agentic task is formulated as a Partially Observable Markov Decision Process (POMDP) ℰ=⟨𝒮,𝒜,𝒪,𝒯,ℛ⟩{\mathcal{E}}=\left\langle{\mathcal{S}},{\mathcal{A}},{\mathcal{O}},{\mathcal{T}},{\mathcal{R}}\right\rangle with state space 𝒮{\mathcal{S}}, action space 𝒜{\mathcal{A}}, and observation space 𝒪{\mathcal{O}}.
The transition function 𝒯​(s,a)→(s′,o){\mathcal{T}}(s,a)\rightarrow(s^{\prime},o) is deterministic, and it is determined by the implementation of the environment. Specifically, it executes an action a∈𝒜a\in{\mathcal{A}} in the environment and returns the next state and observation.
The reward function ℛ{\mathcal{R}} returns the reward given the terminal state sTs\_{T}.
The terminal state is arrived when the transition function receives the special action (e.g., finish\_task).

An LLM agent interacts with the environment to get information for making a decision to achieve a given task o0o\_{0} through multiple steps.
For each step tt, the LLM ℳ{\mathcal{M}} generates the action ata\_{t} followed by its reasoning at each step (Yao et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib53); Wang et al., [2024a](https://arxiv.org/html/2510.00615v2#bib.bib41)) given the interaction history 𝒉t−1=(o0,a0,o1,a1,⋯,ot−1,at−1){\bm{h}}\_{t-1}=(o\_{0},a\_{0},o\_{1},a\_{1},\cdots,o\_{t-1},a\_{t-1}) and the latest observation oto\_{t}:

|  |  |  |  |
| --- | --- | --- | --- |
|  | ℳ​(ot,𝒉t−1;θ,𝒫𝖺𝗀𝖾𝗇𝗍)↦at,{\mathcal{M}}(o\_{t},{\bm{h}}\_{t-1};\theta,{\mathcal{P}}\_{\sf agent})\mapsto a\_{t}, |  | (1) |

where θ\theta refers to the pre-trained parameters of the LLM and 𝒫𝖺𝗀𝖾𝗇𝗍{\mathcal{P}}\_{\sf agent} is the prompt that consists of a general environment description, tools, output format, and few-shot examples in natural language.

#### Cost function for context.

We assume that the LLM agent’s parameters θ\theta and the task and system prompt 𝒫𝖺𝗀𝖾𝗇𝗍{\mathcal{P}}\_{\sf agent} are fixed.
We define a cost function 𝒞{\mathcal{C}} that measures the cost of encoding the dynamic context during action generation at each step such as 𝒪​(n){\mathcal{O}}(n) computational cost of a transformer for decoding given nn input tokens.
The cost function takes the interaction history 𝒉t−1{\bm{h}}\_{t-1}, and the latest observation oto\_{t} as input and returns the per-step cost:

|  |  |  |  |
| --- | --- | --- | --- |
|  | C​(𝑯)=∑t=1T𝒞​(𝒉t−1,ot),C({\bm{H}})=\sum\nolimits\_{t=1}^{T}{\mathcal{C}}({\bm{h}}\_{t-1},o\_{t}), |  | (2) |

where CC is the total cost of completing the task, 𝑯={𝒉t−1,ot}t=1T{\bm{H}}=\{{\bm{h}}\_{t-1},o\_{t}\}\_{t=1}^{T} denotes the sequence of history and observation of each step.
Typically, CC is proportional to the summation of token lengths of action and observations in each step, 𝒉t−1{\bm{h}}\_{t-1} and oto\_{t}.
While the prompt cost is static and can be budgeted in advance, the costs from interaction histories are unbounded, leaving the user with only two options: terminate the task early or truncate the context heuristically to a maximum length.
This raises the central question: *how can we compress context more effectively than such heuristics?*

### 3.2 History & Observation Compression with LLMs

To address this challenge, we use an LLM f​(⋅;ϕ,𝒫)f(\cdot;\phi,{\mathcal{P}}), parameterized by pre-trained weights ϕ\phi and a compression guideline 𝒫{\mathcal{P}}, to minimize context cost defined in [Equation 2](https://arxiv.org/html/2510.00615v2#S3.E2 "2 ‣ Cost function for context. ‣ 3.1 Problem Formulation ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") (e.g., summarize the given interaction history).
As in [Equation 1](https://arxiv.org/html/2510.00615v2#S3.E1 "1 ‣ Task. ‣ 3.1 Problem Formulation ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), the LLM receives two inputs at each step: the interaction history 𝒉t−1{\bm{h}}\_{t-1} and the latest observation oto\_{t}.
This introduces two options for context compression:

#### History compression.

The interaction history accumulates both environment observations and agent actions.
In long-horizon tasks, this history can grow excessively large.
To manage its length, we apply history compression only when the history length exceeds a predefined threshold T𝗁𝗂𝗌𝗍T\_{\sf hist}:

|  |  |  |  |
| --- | --- | --- | --- |
|  | 𝒉t′=f​(𝒉t;ϕ,𝒫𝗁𝗂𝗌𝗍)​if ​|𝒉t|>T𝗁𝗂𝗌𝗍,𝒉t​otherwise.{\bm{h}}\_{t}^{\prime}=f({\bm{h}}\_{t};\phi,{\mathcal{P}}\_{\sf hist})\;\;\text{if }|{\bm{h}}\_{t}|>T\_{\sf hist},\quad{\bm{h}}\_{t}\;\;\text{otherwise}. |  | (3) |

The compressed history 𝒉t′{\bm{h}}\_{t}^{\prime} replaces the raw history in [Equation 1](https://arxiv.org/html/2510.00615v2#S3.E1 "1 ‣ Task. ‣ 3.1 Problem Formulation ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").
This selective compression ensures that the overhead of invoking the compressor is incurred only when necessary (Smith, [2025](https://arxiv.org/html/2510.00615v2#bib.bib35)).

#### Latest observation compression.

Given an action aa, the environment returns an observation oo according to the transition function 𝒯​(s,a)→(s′,o)\mathcal{T}(s,a)\rightarrow(s^{\prime},o).
We similarly apply observation compression only when the observation length exceeds a threshold T𝗈𝖻𝗌T\_{\sf obs}:

|  |  |  |  |
| --- | --- | --- | --- |

This mechanism avoids unnecessary overhead when oto\_{t} is already short, while still reducing redundant or distracting content in long observations (Xu et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib48); Deng et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib7); Lee et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib20)).
The compressed one ot′o\_{t}^{\prime} replaces the raw one in [Equation 1](https://arxiv.org/html/2510.00615v2#S3.E1 "1 ‣ Task. ‣ 3.1 Problem Formulation ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") and is stored in the interaction history 𝒉{\bm{h}}.

In both cases, the compressor LLM selects information to preserve based on its learned prior knowledge of importance.
However, there is no guarantee that the salient details required for successful task completion are retained.
The agent context effectively serves as a world model of the environment, encompassing diverse forms of information such as causal relations (e.g., email leaves drafts), evolving states (e.g., account balance), preconditions (e.g., login required), and task-relevant decision cues (e.g., due dates).
Effective context compression must therefore accommodate this heterogeneous and dynamic nature of agent context, ensuring that the most critical signals are preserved for long-horizon reasoning and task success.

#### Optimization objective.

We optimize the compressor parameters ψ≜(ϕ,𝒫)\psi\triangleq(\phi,{\mathcal{P}}) to maximize task reward while minimizing context cost.
At each step tt, the compressor produces either a compressed history 𝒉t′=f𝗁𝗂𝗌𝗍​(𝒉t;ψ){\bm{h}}\_{t}^{\prime}=f\_{\sf hist}({\bm{h}}\_{t};\psi) or observation ot′=f𝗈𝖻𝗌​(ot,𝒉t−1;ψ)o\_{t}^{\prime}=f\_{\sf obs}(o\_{t},{\bm{h}}\_{t-1};\psi).

With the agent ℳ​(⋅;θ,𝒫𝖺𝗀𝖾𝗇𝗍){\mathcal{M}}(\cdot;\theta,{\mathcal{P}}\_{\sf agent}) fixed, the environment induces a trajectory τ​(ψ)\tau(\psi) and terminal state sT​(ψ)s\_{T}(\psi) when the agent conditions on 𝑯′​(ψ){\bm{H}}^{\prime}(\psi).

where λ\lambda is a multiplier and the expectations are over tasks.

#### Challenges.

The optimization objective in [Equation 6](https://arxiv.org/html/2510.00615v2#S3.E6 "6 ‣ Optimization objective. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") is difficult to optimize in practice because there is no gold supervision for compression, the reward is sparse and only revealed at the end of the trajectory, and the context cost is defined over discrete quantities, which precludes direct gradient computation.
While these properties naturally motivate reinforcement learning (RL) (Sutton & Barto, [2018](https://arxiv.org/html/2510.00615v2#bib.bib36)), applying RL to this setting introduces additional obstacles:
(1) updating the parameters ϕ\phi of a LLM with RL can be computationally prohibitive,
(2) environment roll-outs are extremely expensive since each reward requires multi-step executions of both agent and compressor LLMs, and
(3) policy gradient estimates suffer from high variance because compression quality is only indirectly evaluated through eventual task success.

### 3.3 Optimizing Compression Guidelines

To overcome these challenges, we propose to optimize compression guidelines 𝒫{\mathcal{P}} (natural language prompts) for context compression, rather than fine-tuning model parameters ϕ\phi.
Trajectories under compressed contexts provide *dense signals* about the quality of compression.
For example, if the agent fails with compressed context while succeeding without compression, this indicates that the compressed context may have lost crucial information.
Such trajectory-level comparisons yield richer feedback than scalar rewards (e.g., binary task success).

We instantiate this idea as prompt optimization using an LLM as the optimizer, where the natural language prompt 𝒫{\mathcal{P}} is refined via feedback expressed in natural language (Yang et al., [2024a](https://arxiv.org/html/2510.00615v2#bib.bib51); Yüksekgönül et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib55); Khattab et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib14)).
We introduce compression guideline optimization based on *contrastive task feedback*.

On the training set 𝒟𝗍𝗋𝖺𝗂𝗇{\mathcal{D}}\_{\sf train}, we run the LLM agent both without and with context compression to obtain baseline context 𝑯{\bm{H}} and compressed context 𝑯′{\bm{H}}^{\prime}.
We collect tasks where the agent succeeds with 𝑯{\bm{H}} but fails with 𝑯′{\bm{H}}^{\prime}, forming a contrastive subset 𝒟𝖼𝗈𝗇𝗍{\mathcal{D}}\_{\sf cont}.
For each task in 𝒟𝖼𝗈𝗇𝗍{\mathcal{D}}\_{\sf cont}, we query a optimizer LLM with the context before and after compression to obtain natural language feedback:

|  |  |  |  |
| --- | --- | --- | --- |
|  | Feedback=LLM​(Feedback Instruction,𝑯,𝑯′).\displaystyle\text{Feedback}=\text{LLM}(\text{Feedback Instruction},{\bm{H}},{\bm{H}}^{\prime}). |  | (7) |

This feedback serves as a natural language gradient (Yüksekgönül et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib55)), indicating how the compression guideline 𝒫{\mathcal{P}} should be refined.
We then aggregate feedback from multiple trajectories:

|  |  |  |  |
| --- | --- | --- | --- |
|  | 𝒫(1)=LLM(Update Instruction,𝒫(0),∥i=1nFeedbacki),\displaystyle{\mathcal{P}}^{(1)}=\text{LLM}(\text{Update Instruction},{\mathcal{P}}^{(0)},\textstyle\|\_{i=1}^{n}\text{Feedback}\_{i}), |  | (8) |

where ∥\| is concatenation of feedbacks from each task, which corresponds to a batch optimization step in textual gradient descent (Yüksekgönül et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib55)).
We also generate multiple candidate prompts {𝒫k(1)}\{{\mathcal{P}}\_{k}^{(1)}\}, evaluate them on 𝒟𝖼𝗈𝗇𝗍{\mathcal{D}}\_{\sf cont}, and select the best-performing one.
We refer this process as *utility maximization* step  ut¯¯\overline{\underline{\textsc{ut}}} as it primarily maximizes the first term (task reward) of [Equation 6](https://arxiv.org/html/2510.00615v2#S3.E6 "6 ‣ Optimization objective. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

However, optimizing only for reward may neglect the context cost (second term in [Equation 6](https://arxiv.org/html/2510.00615v2#S3.E6 "6 ‣ Optimization objective. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")).
To address this, motivated by alternating optimization, we perform a second iteration that conditions only on successful task with compressed context, asking the LLM to generate feedback about which information was actually used during execution.
This refines 𝒫(1)→𝒫(2){\mathcal{P}}^{(1)}\rightarrow{\mathcal{P}}^{(2)}, encouraging shorter yet sufficient contexts.
We refer this additional process as *compression maximization* step  co¯¯\overline{\underline{\textsc{co}}} as it minimizes the second term (context cost) of [Equation 6](https://arxiv.org/html/2510.00615v2#S3.E6 "6 ‣ Optimization objective. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

We illustrate overall process in [Figure 3](https://arxiv.org/html/2510.00615v2#S3.F3 "Figure 3 ‣ Challenges. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"). Algorithm [1](https://arxiv.org/html/2510.00615v2#alg1 "Algorithm 1 ‣ Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") and prompts are in [Appendix B](https://arxiv.org/html/2510.00615v2#A2 "Appendix B Experimental Setup Details ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

### 3.4 Distilling Context Compression into Small Models

While compression guideline optimization enables effective compression, repeatedly invoking the large LLM for compression adds substantial overhead.
To reduce this cost, we distill the compressor into a smaller model.
The teacher with optimized guideline 𝒫∗{\mathcal{P}}^{\*} (parameters ϕ𝖳\phi\_{\sf T}) generates compressed outputs 𝒚{\bm{y}} from input 𝒙{\bm{x}}, which supervise the student (parameters ϕ𝖲\phi\_{\sf S}).
We train the student with a cross-entropy objective (Kim & Rush, [2016](https://arxiv.org/html/2510.00615v2#bib.bib16)) with input-output pair (𝒙,𝒚)({\bm{x}},{\bm{y}}),
where (𝒙,𝒚)=(𝒉t,𝒉t′)({\bm{x}},{\bm{y}})=({\bm{h}}\_{t},{\bm{h}}\_{t}^{\prime}) for [Equation 3](https://arxiv.org/html/2510.00615v2#S3.E3 "3 ‣ History compression. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") or (𝒙,𝒚)=((𝒉t−1,ot),ot′)({\bm{x}},{\bm{y}})=(({\bm{h}}\_{t-1},o\_{t}),o\_{t}^{\prime}) for [Equation 4](https://arxiv.org/html/2510.00615v2#S3.E4 "4 ‣ Latest observation compression. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"):

|  |  |  |  |
| --- | --- | --- | --- |
|  | minϕ𝖲⁡𝔼(𝒙,𝒚)∼𝒟𝗍𝗋𝖺𝗂𝗇+​[−∑n=1L𝒚log⁡f​(𝒚n∣𝒙,𝒚<n;ϕ𝖲,𝒫∗)],\min\_{\phi\_{\sf S}}\;\mathbb{E}\_{({\bm{x}},{\bm{y}})\sim\mathcal{D}^{+}\_{\sf train}}\Bigg[-\sum\_{n=1}^{L\_{\bm{y}}}\log f({\bm{y}}\_{n}\mid{\bm{x}},{\bm{y}}\_{<n};\phi\_{\sf S},{\mathcal{P}}^{\*})\Bigg], |  | (9) |

where 𝒟𝗍𝗋𝖺𝗂𝗇+\mathcal{D}^{+}\_{\sf train} denotes tasks where the teacher succeeds with compressed context.

Once trained, the student replaces the teacher during inference, decoupling decision making from compression.
This two-stage pipeline, guideline optimization then distillation, achieves effective compression with a much smaller model (|ϕ𝖳|≫|ϕ𝖲||\phi\_{\sf T}|\gg|\phi\_{\sf S}|):

|  |  |  |  |
| --- | --- | --- | --- |
|  | f​(⋅;ϕ𝖳,𝒫)→prompt optimizationf​(⋅;ϕ𝖳,𝒫∗)→distillationf​(⋅;ϕ𝖲,𝒫∗).f(\cdot;\phi\_{\sf T},{\mathcal{P}})\xrightarrow{\;\text{prompt optimization}\;}f(\cdot;\phi\_{\sf T},{\mathcal{P}}^{\*})\xrightarrow{\;\text{distillation}\;}f(\cdot;\phi\_{\sf S},{\mathcal{P}}^{\*}). |  | (10) |

## 4 Experiments

We evaluate Acon on three challenging benchmarks that require multi-step interactions across diverse domains.
Our experiments are designed to address the following key questions:

- •

  How well does Acon improve token efficiency while preserving performance? ([Section 4.2](https://arxiv.org/html/2510.00615v2#S4.SS2 "4.2 Overall performance and token efficiency on LLMs ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"))
- •

  Does distilling the compressor reduce its size while maintaining agent performance? ([Section 4.3](https://arxiv.org/html/2510.00615v2#S4.SS3 "4.3 Compressor Distillation ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"))
- •

  Can Acon help small, distilled LM agents perform better under long contexts? ([Section 4.4](https://arxiv.org/html/2510.00615v2#S4.SS4 "4.4 Acon for distilled small agents ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"))

### 4.1 Experimental Setup

#### Benchmarks & Metrics.

We focus on long-horizon agentic task benchmarks that require 10+10+ interaction steps on average:
(1) AppWorld (Trivedi et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib38)): Main benchmark with 9 simulated apps (e.g., Venmo, Spotify, SimpleNote) and ∼\sim100 simulated users. Performance is measured by task completion score.
(2) OfficeBench (Wang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib42)): Productivity tasks across 6 apps (e.g., Word, Excel, Email), operating on simulated documents. Performance is measured by benchmark-defined accuracy functions.
(3) 8-objective QA (Kwiatkowski et al., [2019](https://arxiv.org/html/2510.00615v2#bib.bib18); Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58)): QA benchmark where agents interact with a search tool to answer 8 questions and output a consolidated answer set. Performance is the average of Exact Match (EM) and F1 scores across 8 questions.

In addition to task-specific performance metrics, we report three token efficiency metrics following prior work (Zhang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib56); Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58)):
(1) Steps: The average number of interaction steps per task.
(2) Peak Tokens: The maximum context length encountered across all steps.
(3) Dependency: The cumulative dependency of each generated action on prior tokens, measuring how much generation relies on the context history.
Full details are provided in the [Appendix B](https://arxiv.org/html/2510.00615v2#A2 "Appendix B Experimental Setup Details ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

#### Baselines.

(1) No Compression: full uncompressed context.
(2) FIFO: keep the most recent kk interactions, discarding earlier ones (Yang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib52)).
(3) Retrieval: select kk past interactions most similar to the current query via embedding search (Xu et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib49)).
(4) LLMLingua: extractive compression with an encoder-only LM (Jiang et al., [2023](https://arxiv.org/html/2510.00615v2#bib.bib10); Pan et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib28)).
(5) Prompting: naive baseline using a general compression instruction (Smith, [2025](https://arxiv.org/html/2510.00615v2#bib.bib35); Lee et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib20)).

#### Our Methods.

We evaluate two versions of Acon.
(1) Acon  ut¯¯\overline{\underline{\textsc{ut}}} utilizes an *optimized guideline* for context compression after utility maximization step.
(2) Acon  ut¯¯\overline{\underline{\textsc{ut}}}  co¯¯\overline{\underline{\textsc{co}}} applies compression maximization step  co¯¯\overline{\underline{\textsc{co}}} after utility maximization  ut¯¯\overline{\underline{\textsc{ut}}}, aiming for shorter but informative compression.

### 4.2 Overall performance and token efficiency on LLMs

In [Table 1](https://arxiv.org/html/2510.00615v2#S4.T1 "Table 1 ‣ Our Methods. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") and [Table 2](https://arxiv.org/html/2510.00615v2#S4.T2 "Table 2 ‣ Our Methods. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), we first evaluate Acon using on gpt-4.1 (OpenAI, [2025b](https://arxiv.org/html/2510.00615v2#bib.bib24)) for both agent and compressor, which already achieves strong results on three long-horizon benchmarks.

For history compression, as shown in [Table 1](https://arxiv.org/html/2510.00615v2#S4.T1 "Table 1 ‣ Our Methods. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), on AppWorld, Acon reduces peak tokens by over 25% while preserving the accuracy of the no compression upper bound, outperforming all baselines that suffer severe degradation on medium and hard tasks spanning longer steps.
On OfficeBench ([2(a)](https://arxiv.org/html/2510.00615v2#S4.T2.st1 "2(a) ‣ Table 2 ‣ Our Methods. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")), Acon lowers peak context size by nearly 30% while maintaining accuracy above 74%.

For observation compression, Acon consistently outperforms all baselines confirming that compression guideline optimization is effective for compressing not only history but also raw observations.

Applying only the utility maximization step ( ut¯¯\overline{\underline{\textsc{ut}}}) improves performance while reducing token cost across all benchmarks, whereas the compression maximization step ( co¯¯\overline{\underline{\textsc{co}}}) further lowers token cost but may slightly hurt accuracy, except in AppWorld where it even yields additional gains.

### 4.3 Compressor Distillation

We distill the compressor with optimized guidelines after  ut¯¯\overline{\underline{\textsc{ut}}} step into smaller models such as Qwen3-14B, Qwen3-8B (Yang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib50)), and Phi-4 (Abdin et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib1)) using LoRA (Hu et al., [2022](https://arxiv.org/html/2510.00615v2#bib.bib9)).

We also find that gpt-4.1-mini, even without distillation, can serve as a lightweight compressor in OfficeBench and QA.
These results confirm that small models are sufficient for compression, enabling the expensive LLM to be only reserved for the agent.

### 4.5 Analysis

#### Compression threshold: moderate value yields the best trade-off.

In [Figure 6](https://arxiv.org/html/2510.00615v2#S4.F6 "Figure 6 ‣ 4.4 Acon for distilled small agents ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), we provide ablations on threshold for compression in [Equation 3](https://arxiv.org/html/2510.00615v2#S3.E3 "3 ‣ History compression. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents") and [Equation 4](https://arxiv.org/html/2510.00615v2#S3.E4 "4 ‣ Latest observation compression. ‣ 3.2 History & Observation Compression with LLMs ‣ 3 Agent Context Optimization (Acon) ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").
Results show that smaller thresholds reduce tokens but incur more frequent compression calls and degrade accuracy, while larger thresholds preserve accuracy with higher cost.
Moderate values (4096 for history, 1024 for observation) provide the best trade-off, maintaining accuracy close to no compression while still reducing peak tokens substantially.

#### Prompt optimizer: o3 + contrastive feedback works best.

We analyze how the choice of optimizer and the use of contrastive feedback affect compression guideline quality.
As shown in [Table 3](https://arxiv.org/html/2510.00615v2#S4.T3 "Table 3 ‣ Figure 7 ‣ 4.4 Acon for distilled small agents ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), the default o3 with contrastive feedback yields the best performance, while removing contrastive feedback (only using failed trajectories) or switching to other models results in lower accuracy.

#### Limitation: Cost Analysis.

Acon compresses context while maintaining performance, but one limitation remains:
the compressor module can introduce extra cost, and history compression can increase costs in agentic tasks.
We provide cost analysis, and use an API cost metric that accounts for cheaper cached input tokens to approximate computational overhead.
As shown in [Figure 7](https://arxiv.org/html/2510.00615v2#S4.F7 "Figure 7 ‣ 4.4 Acon for distilled small agents ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), observation compression reduces cost by compressing inputs, whereas history compression rarely helps due to KV-cache overhead.
Compressor distillation partly alleviates this issue by replacing expensive LLM calls with smaller models.
We include detailed discussions in [Appendix A](https://arxiv.org/html/2510.00615v2#A1 "Appendix A Limitations & Future Work ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

## 5 Conclusion

We presented Agent Context Optimization (Acon), a unified framework that systematically compresses both interaction histories and environment observations for long-horizon LLM agents. Unlike prior work that relies on naive prompting or narrow domains, Acon introduces compression guideline optimization in natural language space, enabling adaptive and model-agnostic compression.
Experiments on AppWorld, OfficeBench, and Multi-objective QA show that Acon reduces peak tokens by 26-54% while maintaining or even improving task success.
Beyond efficiency, we demonstrate that optimized compressors can be distilled into smaller models, substantially lowering overhead without sacrificing performance.
Moreover, by supplying concise yet informative contexts, Acon allows small agents such as Qwen3-14B to approach the performance of much larger models.
Overall, our findings highlight that Acon lays a foundation for more general, cost-effective, and deployable long-horizon LLM agents.

We will also release our codebase to enable the research community to fully reproduce, verify, and extend our work on long-horizon LLM agents.

## Appendix A Limitations & Future Work

Our work addresses the context management problem in long-horizon LLM agents and proposes a framework for optimized context compression. While the method effectively reduces token costs with minimal performance degradation, it also presents several limitations.

A primary limitation is computational overhead. As discussed in [Section 4.5](https://arxiv.org/html/2510.00615v2#S4.SS5 "4.5 Analysis ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), history compression can in some cases increase total cost, since additional steps may be required to complete challenging tasks with the compressed history. Moreover, it breaks the KV-cache of transformer-based LLMs, which forces re-computation of compressed histories. This effect is particularly evident in the FIFO baseline. Observation compression alleviates some of this overhead, but the generative compression procedure itself introduces latency, slowing down agent response time (Lee et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib20)). A promising future direction is the development of KV-cache–level compression or eviction strategies. Prior work has considered KV-cache compression for single-step reasoning (Zhang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib56)), long documents (Xiao et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib46); Willette et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib44)), and long conversations (Kim et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib15)). However, its role in multi-turn, long-horizon agents remains underexplored.

Another limitation is model coverage. Our experiments primarily evaluate GPT models due to budgetary constraints. Although the framework is designed to be model-agnostic, its generalizability to other foundation models such as Gemini (Comanici et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib5)) or Claude (Anthropic, [2024b](https://arxiv.org/html/2510.00615v2#bib.bib3)) remains unverified. Similarly, we were unable to include large-scale open-source models such as DeepSeek-R1 (DeepSeek-AI et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib6)) or Qwen3-235B (Yang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib50)) due to limited resources. Extending the analysis to these models would provide stronger evidence of robustness and broaden the applicability of our conclusions.

## Appendix B Experimental Setup Details

### B.1 Datasets

#### AppWorld (Trivedi et al., [2024](https://arxiv.org/html/2510.00615v2#bib.bib38)).

AppWorld is our primary benchmark, providing a high-quality execution environment that integrates nine everyday applications (Spotify, SimpleNote, Amazon, Venmo, Gmail, Splitwise, File system, Todoist, and Phone) through 457 APIs.
It also includes realistic simulations of approximately 100 functional users.
This benchmark is particularly suitable for evaluating long-horizon productivity agents, as its multi-step tasks require an average of 42.5 API calls per task.
We follow the official split, using 90 training tasks for guideline optimization and distillation, and 168 test-normal tasks for evaluation.
An example trajectory from AppWorld is provided in Example [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

#### OfficeBench (Wang et al., [2024b](https://arxiv.org/html/2510.00615v2#bib.bib42)).

OfficeBench is a benchmark for office automation using applications such as Word, Excel, PDF, Calendar, Email, Shell, and Calculator.
It evaluates the ability of agents to coordinate across multiple apps to complete complex tasks, making it well suited for long-horizon scenarios.
Tasks are categorized as 1-app, 2-app, or 3-app depending on the number of applications required.
We restrict our experiments to text-related tasks, excluding those requiring OCR, as OCR quality could confound the evaluation.
Since no official split is available, we randomly partition the tasks into training and test sets with a 1:1 ratio, resulting in 92 training tasks and 95 test tasks.
We additionally refine the dataset by removing ambiguous tasks and ensuring that synthetic files (testbeds) are not shared across splits.

#### 8-Objective QA (Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58)).

The 8-objective QA benchmark simulates deep research-style agentic tasks.
Unlike conventional multi-hop QA, which requires answering a single question using multiple pieces of evidence, this benchmark poses eight distinct questions within one task, and the agent must provide answers to all of them at the end.
This design creates a more challenging setting for long-horizon agents.
Following Zhou et al. ([2025](https://arxiv.org/html/2510.00615v2#bib.bib58)), we construct each task by grouping eight questions together.
Questions are drawn from NaturalQuestions (Kwiatkowski et al., [2019](https://arxiv.org/html/2510.00615v2#bib.bib18)), resulting in 100 training tasks (from the train split) and 100 test tasks (from the test split).
For retrieval, we use a BM25 retriever over the 2018 Wikipedia knowledge base, following Jin et al. ([2025](https://arxiv.org/html/2510.00615v2#bib.bib13)).

### B.2 Evaluation Metrics

For efficiency evaluation, we adopt two metrics—*peak tokens* and *dependency*—introduced in LightThinker (Zhang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib56)) and MEM1 (Zhou et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib58)).

#### Peak tokens.

Peak tokens are measured as the maximum number of tokens observed in any single sequence throughout the agent’s trajectory, excluding system prompts.
This metric serves as a proxy for inference-time memory requirements and corresponds to the maximum peak shown in [Figure 2](https://arxiv.org/html/2510.00615v2#S1.F2 "Figure 2 ‣ 1 Introduction ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").

#### Dependency.

Dependency is defined as the area under the curve in [Figure 2](https://arxiv.org/html/2510.00615v2#S1.F2 "Figure 2 ‣ 1 Introduction ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").
At each step tt, given the number of input tokens ni(t)n\_{i}^{(t)} and output tokens no(t)n\_{o}^{(t)}, it is calculated as:

|  |  |  |  |
| --- | --- | --- | --- |
|  | ∑t∈[T](ni(t)+2​no(t))×no(t)2.\sum\_{t\in[T]}\frac{(n\_{i}^{(t)}+2n\_{o}^{(t)})\times n\_{o}^{(t)}}{2}. |  | (11) |

This metric approximates the cumulative computational cost incurred by action generation across the trajectory.

#### API Cost.

For the cost analysis in [Section 4.5](https://arxiv.org/html/2510.00615v2#S4.SS5 "4.5 Analysis ‣ 4 Experiments ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), we use the official OpenAI pricing (as of September 2025) for gpt-4.1 and gpt-4.1-mini (OpenAI, [2025b](https://arxiv.org/html/2510.00615v2#bib.bib24)). Specifically, gpt-4.1 is priced at $3.00 per 1M input tokens, $0.75 per 1M cached input tokens, and $12.00 per 1M output tokens. For gpt-4.1-mini, the costs are $0.80 per 1M input tokens, $0.20 per 1M cached input tokens, and $3.20 per 1M output tokens.
For Qwen3-14B (Yang et al., [2025](https://arxiv.org/html/2510.00615v2#bib.bib50)), since no official API pricing is available, we approximate the cost using OpenRouter111<https://openrouter.ai/>
: $0.06 per 1M input tokens, $0.015 per 1M cached input tokens, and $0.24 per 1M output tokens.

### B.3 Implementation Details & Hyperparameters

#### API Inference.

We set temperature 0.0 and fix the seed 42.
Note that there is still non-determinism with fixing the seed and setting temperature as 0.
To reduce the instability, we use the API snapshot form Azure OpenAI endpoint gpt-4.1-2025-04-14 and gpt-4.1-mini-2025-04-14.

#### Compression.

For history compression, we set Thist=4096T\_{\text{hist}}=4096 for AppWorld and OfficeBench, and 20482048 for 8-objective QA.
We keep the last action, observation pair to preserve the latest information. This is the same for Acon and all baselines.
For observation compression, we set Tobs=1024T\_{\text{obs}}=1024 for AppWorld, 512512 for OfficeBench, and 400400 for 8-objective QA.

#### Prompt Optimization.

We use the OpenAI o3 model (OpenAI, [2025d](https://arxiv.org/html/2510.00615v2#bib.bib26)) for both analysis and update of prompts.
During the update stage, we sample 5 candidate prompts and select the one that performs best on a subset of the training set.

The prompts used in each stage and step are provided as follows:

- •

  Analysis prompt for  ut¯¯\overline{\underline{\textsc{ut}}} step: Prompt [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")
- •

  Update prompt for  ut¯¯\overline{\underline{\textsc{ut}}} step: Prompt [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")
- •

  Analysis prompt for  co¯¯\overline{\underline{\textsc{co}}} step: Prompt [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")
- •

  Update prompt for  co¯¯\overline{\underline{\textsc{co}}} step: Prompt [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents")

We also provide the detailed procedure in Algorithm [1](https://arxiv.org/html/2510.00615v2#alg1 "Algorithm 1 ‣ Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents").
For the subset used in prompt selection during the  ut¯¯\overline{\underline{\textsc{ut}}} step, we consider training tasks in 𝒟𝖼𝗈𝗇𝗍(r){\mathcal{D}}\_{\sf cont}^{(r)} where the agent succeeds without compression but fails with compression.
For the  co¯¯\overline{\underline{\textsc{co}}} step, we use training tasks in 𝒟𝗌𝗎𝖼𝖼(r){\mathcal{D}}\_{\sf succ}^{(r)} where the agent succeeds with compression.

#### Baselines

For FIFO, we keep last 5 interaction turns which fits in similar compression rate in average with Acon.
For retrieval, we also retrieve 4 interaction turns and keep the last turn. We use OpenAI text-embedding-3-large for embedding.
For LLMLingua, we set keep rate as 30% for both history and observation.
For naive prompting, we use the similar prompt with Lee et al. ([2025](https://arxiv.org/html/2510.00615v2#bib.bib20)) and do some human prompt engineering to specialize each prompt to history or observation compression.

#### Compressor & Agent Distillation

Both compressor and agent distillation use LoRA (Hu et al., [2022](https://arxiv.org/html/2510.00615v2#bib.bib9)) with rank 16, α=32\alpha=32, learning rate 10−410^{-4}, 3 epochs, batch size 4, and maximum sequence length 10,00010{,}000.
We adopt linear warmup (5%5\% ratio), weight decay 0.010.01, and AdamW optimizer.
No hyperparameter tuning was performed; the same setup is applied across all models and benchmarks.
We sample a single generation from the teacher for fine-tuning, leaving potential improvements from hyperparameter tuning or multi-sample training for future work.
We use 1 A100 80GB GPU for both training and inference.
For inference of fine-tuned models, we use greedy decoding (temperature 0.0).

#### Case study: history compression turns failure into success.

A notable case study illustrates how history compression enables a smaller agent to succeed on tasks that would otherwise fail.
In the uncompressed trajectory in Example [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), the gpt-4.1-mini agent repeatedly attempted to use the file\_system APIs without managing authentication, leading to persistent 401 Unauthorized errors.
After compressing the history as in Example [E](https://arxiv.org/html/2510.00615v2#A5 "Appendix E LLM Usage ‣ Acon: Optimizing Context Compression for Long-horizon LLM Agents"), however, the compressed history retained only the essential reasoning steps: the need for both username and password, the importance of passing the returned access\_token into subsequent calls, and the absence of proxy APIs in the supervisor app.

This compressed context prevented redundant exploration and guided the agent directly to the correct sequence—login with full credentials, capture the token, and provide it explicitly in show\_directory and delete\_file calls.
As a result, the agent was able to enumerate and remove all .pdf files in  /downloads, a task it had previously failed.
This example highlights how compression does not merely shorten history but clarifies critical dependencies, turning a failure trajectory into a successful one.
