Kiln is a pure-Rust, single-GPU inference server with live LoRA training and evals built in. Drop-in OpenAI API. Hot-swap adapters. SFT, GRPO, and a local eval loop over HTTP — no frontier-LLM judge required. Built for local Qwen3.5-4B workflows on one GPU.

Set up your client

One command — backs up & merges ~/.pi/agent/{models,settings}.json, then makes Kiln pi’s default model.

# Point pi at this Kiln server
kiln pi-setup

# Remote server? pass its URL — /v1 is appended for you
kiln pi-setup --kiln-url http://localhost:8420

Add this provider, then run opencode and pick the model with /models. No API key needed.

~/.config/opencode/opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "kiln": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Kiln (local)",
      "options": { "baseURL": "http://localhost:8420/v1", "apiKey": "unused" },
      "models": { "Qwen3.5-4B": { "name": "Kiln · Qwen3.5-4B" } }
    }
  }
}

Drop-in OpenAI SDK — only base_url changes.

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8420/v1", api_key="unused")

resp = client.chat.completions.create(
    model="Qwen3.5-4B",
    messages=[{"role": "user", "content": "Hello from my agent"}],
)
print(resp.choices[0].message.content)

What is kiln

An inference server you can teach.

Most servers stop at autoregressive decode. Kiln keeps going. Same process serves traffic, trains a LoRA adapter on your scoring signal, and hot-swaps it into production — without ever dropping a request.

OpenAI-compatible inference

/v1/chat/completions, /v1/completions, /v1/embeddings, streaming, function calling. Point any OpenAI client at localhost:8420 and you're done.

Live LoRA training

POST a batch of rollouts and rewards to /v1/train/grpo. The trainer shares VRAM with the model, computes the policy update, and hot-swaps the new adapter on the next forward pass.

Single-GPU, single binary

Pure-Rust workspace, no Python runtime, no Docker required. CUDA or ROCm on Linux, Metal on Apple Silicon, Vulkan elsewhere. Boots in seconds and stays under ~10 GB on A6000.

The killer feature

Online learning over HTTP.

Generate rollouts. Score them with whatever reward function you have lying around. POST them back. The model that serves your next request is the one that just learned.

python grpo_loop.py 
# Drop-in OpenAI client. Same endpoint, same model.
import openai
import requests, json

client = openai.OpenAI(base_url="http://localhost:8420/v1", api_key="unused")

# 1. Generate N rollouts on the same prompt.
prompt = "Write a short, friendly email reply."
rollouts = [client.chat.completions.create(
    model="Qwen/Qwen3.5-4B",
    messages=[{"role": "user", "content": prompt}],
    temperature=1.0, n=1).choices[0].message.content
    for _ in range(8)]

# 2. Score with whatever reward you want.
scored = [{"text": r, "reward": score(prompt, r)} for r in rollouts]

# 3. Send the batch back. Adapter is live on the next request.
requests.post("http://localhost:8420/v1/train/grpo", json={
    "groups": [{
        "messages": [{"role": "user", "content": prompt}],
        "completions": scored,
    }],
    "config": {"output_name": "helpful-v3"},
})
1

You generate.

Standard OpenAI completions. Use any client — the kiln server doesn't care if it's Python, TypeScript, or curl.

2

You score.

Reward is your code, not a config. A regex, a classifier, a human, an evaluator LLM, a unit test result. Whatever signal you have.

3

Kiln learns.

One HTTP call. The trainer runs in-process, computes the GRPO update, swaps the adapter without reloading the base model. Typical end-to-end: a few seconds.

Two front ends

One server, browser or desktop.

Every kiln server ships an embedded dashboard. There's also a Tauri desktop app for the same workflows offline.

Under the hood

Tuned for one model, end to end.

Kiln targets Qwen3.5-4B specifically. The scheduler, paged KV cache, kernels, and quantization are all chosen for its hybrid 24×GDN + 8×GQA layout.

Continuous batching

Sarathi-style chunked prefill. Decode requests merge into a running batch without head-of-line blocking.

pi & opencode backend

kiln pi-setup wires up pi; one provider block wires up opencode. Both serve Qwen3.5-4B with OpenAI-shaped tool calls. Connect ↑

Paged KV cache

Block-allocated KV pages with backend-qualified cross-call prefix reuse. Vulkan currently fresh-prefills under an explicit correctness quarantine.

W4A16 + Marlin

MLP projections quantized to 4-bit weights with bf16 activations. Vendored Marlin GEMM, fused RMSNorm + GDN gates.

Hot-swap LoRA

Adapters live alongside the base weights. Applied per request. Switch policies in milliseconds, no reload.

Bounded online LoRA

Fixed-profile native SFT plus GRPO and OPD with exact resume points. Your data, rewards, and identity-bound teachers stay beside the serving model.

FP8 KV (opt-in)

KILN_MEMORY_KV_CACHE_FP8=1 doubles effective context with no measurable quality loss on Qwen3.5-4B.

Four GPU backends

CUDA on Ampere/Ada/Hopper. ROCm on AMD CDNA/RDNA/Strix Halo. Metal on Apple Silicon (M-series). Vulkan elsewhere. One source tree.

Pure Rust

13-crate workspace. No Python at runtime. cargo build --release --features cuda and you have a server.

Evals as a peer of training

Pluggable scorers (exact_match, regex, tool_call, code, llm_judge, …). Synthesize a suite from any SFT/GRPO dataset. Auto-eval every training run via post_eval. See the eval loop →

The judgment flywheel

A/B preferences from /ui compile into an SFT dataset and train a local judge LoRA, used as the judge_adapter in any future llm_judge scorer.

HTTP API

One binary, every endpoint you need.

POST /v1/chat/completions OpenAI chat with streaming, normalized tools, structured outputs.
POST /v1/completions Classic completion API for legacy clients.
POST /v1/embeddings Hidden-state embeddings from the same model.
POST /v1/train/sft Supervised LoRA training. Send {prompt, completion} pairs.
POST /v1/train/grpo GRPO update. Send rollouts + rewards. Adapter hot-swaps on success.
GET /v1/adapters List, attach, detach LoRA adapters.
POST /v1/eval/run Run a graded eval suite against any adapter. Inline or registered. Full eval API →
POST /v1/judgments A/B/Tie/Skip preferences → SFT dataset → local judge LoRA. The flywheel.
GET /v1/models OpenAI model list. Reports the loaded model and version.
GET /healthz Liveness + readiness probe.
