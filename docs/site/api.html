Server status, metrics, UI, and config

GET /health — server health and diagnostics, including bounded base-weight aggregate and execution-identity summaries, the immutable SFT checkpoint-boundary policy under training.checkpoint_boundary_policy, memory-sampler age/liveness, a separately bounded host-backed tier when present, configured/live CUDA graph policy under decode_runtime.cuda_graphs, ROCm graph full-snapshot availability, entry/byte limits, retained-byte categories, cache actions and closed fallbacks plus independently available live phase/transient telemetry under decode_runtime.rocm_graphs, and reasoned ROCm wait/skip and cleanup-quarantine state under decode_runtime.rocm_synchronization. A real backend without valid execution provenance is not ready.
GET /v1/health — /v1 compatibility alias for the same health and diagnostics response.
GET /metrics — Prometheus metrics for latency, throughput, memory, sampler freshness/liveness, fixed-reason ROCm synchronization, ROCm graph phase/current-pause telemetry independent of the model and graph-runner locks, graph state/capacity/retained and transient bytes/cache actions/capture/replay/closed fallbacks, training progress, and bounded thinking-budget provenance/outcomes.
GET /ui — embedded dashboard for status, runtime configuration including live ROCm graph retained/transient memory, cache state, and phase latency, adapters, training, and chat.
GET /v1/stats/decode — live decode tokens/sec and inter-token latency stats used by the dashboard.
GET /v1/stats/recent-requests — bounded recent chat-completion history with effective thinking-budget provenance and outcomes for the dashboard's request panel.
GET /v1/models — list the served model.
GET /v1/config — return resolved startup policy, the versioned accelerator execution policy, top-level cuda_graphs configured/effective/cache/invariant state, independent top-level rocm_graphs full statistics and rocm_graph_telemetry live phase/transient snapshots with a typed unavailable-reason field beside each, typed batching and streaming-prefill intent/backend/effective policy, actor activity, direct-rendezvous worker/route status, fail-closed speculative diagnostics, device-scoped memory capacity and live availability diagnostics, effective gradient and SFT boundary-checkpoint policy, the resident optimizer implementation/tuple/per-workload admission contract, memory-budget partitions, generation defaults, and the immutable operational snapshot for terminal/agent access, pi resolution, library URL, and cache/session paths. A null live value never means its counters were zero.
GET /v1/debug/model-state — gated trusted-debug state including the complete base-weight shard manifest, execution-provenance record, immutable checkpoint-boundary policy under training.checkpoint_boundary_policy, the same top-level cuda_graphs policy snapshot as config, and the resolved ROCm policy plus the same four graph value/reason fields as config. Do not enable this endpoint merely to collect routine graph telemetry; health carries the operational snapshot.

The generated Observability API Schema is the canonical field, requiredness, nullability, enum, and closed-object contract for these JSON responses and for GET /v1/cache/stats. The generated HTTP API Contract records that health returns the same diagnostic body with HTTP 200 when ready and HTTP 503 when degraded or in maintenance, and records the gated debug endpoint's distinct HTTP 403 and provenance-validation HTTP 500 bodies. The operational guidance below does not redefine those wire contracts.

Check runtime configuration

curl -s http://localhost:8420/v1/config | python3 -m json.tool

The response keeps accelerator, batching, and streaming-prefill intent, backend policy, effective execution, startup capacity resolution, the current safe memory sample, and the budget derived from effective capacity separate. Every *_gib value uses 1 GiB = 1,073,741,824 bytes and is paired with an exact *_bytes value where the response exposes both units. Its top-level accelerator_runtime object is immutable startup policy. Top-level cuda_graphs reports the requested and profile-effective single-row CUDA graph policy, the startup-fixed cache bound, mandatory stable metadata, and unavailable batched route. The trusted debug response repeats that exact object at top-level cuda_graphs so a qualification receipt can bind the launch policy without reconstructing it from process state. Top-level rocm_graphs is a nonblocking full cache/counter snapshot, while rocm_graph_telemetry is the separate current/completed phase and transient-candidate snapshot; each has its own typed unavailable-reason sibling. The Playground uses the same response to preview the resolved thinking token/time pair before send, marking each dimension as server- or request-owned.

The typed kt_api_mode replaces the former per-operation KILN_USE_KT_API_*, KILN_DISABLE_KT_API_*, and KILN_USE_KT_PAGED_KV_* debug switches. Those names are intentionally not accepted as aliases because they permitted unvalidated, order-dependent route combinations.

cuda_kernel_profile is installed before CUDA backend construction and cannot change between requests. It owns full-attention QKV projection; GDN A/B projection, prefill projection and gates, base/gates/gated-RMSNorm, fused decode, unexpanded Q/K, both Q/K-normalized recurrent variants, and multi-block full-chunk forward; fused convolution; and decode LoRA add. Former CUDA-specific per-kernel variables are not aliases.

rocm_kernel_profile is one complete model/tensor policy installed before device creation. Its 45 accelerated decisions cover backend dispatch, exact long attention, QKV preparation, W8/W8A8 decode, sampled LM-head execution, split Q/gate F32 output, and multi-block GDN prefill plus split and GQA paged-attention specialization and native flash-attention forward/backward execution. Its other thirty leaves keep training MLP and split Q/gate projection, paged-attention splitting, safe concat, finite checks, RMSNorm, and flash tiling bounded at exact documented geometries. qualified enables 43 of 45 accelerated routes, keeping the slower gfx1151 multi-block experiment and correctness-disabled fused RMSNorm off; portable_fallback declines all 45 accelerated routes but keeps the thirty safety leaves; experimental_multiblock is the qualified set plus that experiment and still keeps fused RMSNorm off. Retired per-kernel enable/disable variables are not aliases. A process cannot combine individual routes or change loading, forward, tape-forward, backend, Rust tensor, or C++ launcher dispatch between operations.

Vulkan device policy has schema kiln.vulkan-device-policy.v1. The typed startup values are installed once before Vulkan logical-device creation; a same-value reinstall is idempotent and a conflicting late owner fails. The former GGML_VK_VISIBLE_DEVICES behavior is removed rather than accepted as configuration. Driver-level selectors remain external identity remaps and fail the device-scoped memory-probe identity gate.

full_attention_score_budget_mib replaces eight undocumented materialized-score, ROCm online-score, and tile-size environment controls. Those controls are not aliases. They previously let the model and ROCm flash planners parse different permissive values during execution and derive geometry from changing free-memory snapshots, including a materialized ceiling as high as 32 GiB. Policy v12 installs one bounded ceiling before execution. The memory governor can reject a plan whose exact working set is no longer available, but it cannot silently shrink, expand, or retile that plan between layers or requests.

Both matmul fields default to auto. The strided-batched selector applies the qualified gfx115x large-attention correctness guard, while the BF16-output selector applies the ROCm 7.2 large-projection and low-rank workaround. These are immutable shape/dtype decisions stored in the primary context; they do not consult live memory or process environment during inference. Four former force/disable variables are strict warning aliases resolved only at startup. Conflicting aliases fail startup. The two former ad hoc trace variables were removed rather than promoted to configuration.

The byte limit counts requested physical bytes held by graph-stable direct I/O tensors, freeze-pointer capture arenas, each retained private-stream hipBLASLt workspace, and recurrent/conv state in every runner-owned owner slot, including active slot state that outlives graph eviction. Accounting deduplicates one physical allocation across tensors, graphs, and categories by device ordinal plus allocation identity; shared slot state is counted once per allocation even when one owner retains several graphs. retained_bytes is the deduplicated sum, while the four retained_*_bytes fields preserve category attribution. peak_retained_bytes advances after slot creation or cache admission and is never reported below the current total.

HIP does not expose byte sizes for a retained graph, executable, stream, or either ordering event. These five objects per graph are reported through opaque_native_object_count but are excluded from retained_bytes; allocator-pool slack is excluded too. Therefore retained_bytes_accounting_complete=true means every byte-accounted tensor mapped to allocation metadata, not that opaque driver overhead is zero. Live memory pressure complements rather than expands the immutable byte limit.

legacy_host_barriers preserves the qualified host waits, including a device-wide external-yield drain. stream_ordered requires the experimental profile and skips only explicitly proven same-stream dependency barriers; host readbacks, buffer lifetimes, in-place mutation, reclamation, graph transitions, and error recovery remain synchronized. External yield waits on the primary stream. ROCm graph replay records completion on its capture stream and orders that event into the primary stream first.

A warm candidate that performs a host upload emits event=rocm_graph_capture_host_transfer once per unique source site. Each record carries the same closed fallback reason, build-source file/line/column, dtype, elements and bytes per copy, copy count, and total bytes. Health flattens these two authorities into decode_runtime.rocm_graphs. Full-statistic fields are null when unavailable. Its state is enabled or disabled when full statistics exist, busy only for model_runner_busy or graph_runner_busy, and unavailable for backend_without_graph_runner or either poisoned-lock reason. unavailable_reason governs full statistics; phase_telemetry_available and phase_telemetry_unavailable_reason govern the current phase, five summaries, and transient-byte fields independently. The dashboard uses config for static policy/full-stat context and its two-second health poll to refresh Graph live and Graph current phase, including typed unavailable reason and elapsed time; it never fabricates zeroes for missing snapshots.

capture_successes means native graph instantiation and its first launch succeeded; cache_admission_successes is the retained, replayable subset, and the entry, byte, and accounting post-capture rejection counters explain their difference. Pre-capture skips are intentionally separate. Entry/known-byte saturation is reclaimed before candidate allocation; after the settled warm Record pass, exact pre-native accounting, matching-device pressure, and atomic global reservation must pass before native capture. Post-capture admission is a defensive concurrency recheck. Candidate-alone byte and incomplete-accounting results make the geometry non-capture-safe for the runner lifetime. Aggregate budget suppression clears after ownership or budget relief; global-reservation denial retries only after matching-device cached headroom is sufficient. A memory-governor selector mismatch fails closed rather than consuming another accelerator's budget. These distinct rules prevent a per-token warm/allocation storm.

Exact candidate size is unavailable until its warm pass allocates stable I/O, arena buffers, and private-stream workspace. The transient fields expose that residual rather than retained cache residency. The five fixed phases attribute headroom reclamation, warm allocation and execution, reservation/accounting, native capture plus settled first launch plus defensive cache admission/publication and blocking committed governor debit, and rejected-candidate cleanup. rejected_candidate_cleanup starts only when an unretained candidate enters destruction and settlement. The phase handle is independent of both runner locks, so health and phase metrics can show an in-progress phase while the full cache snapshot is busy or poisoned. Governor reads fail closed unless their device selector matches the runner, and warm-pass host-copy observation is scoped so unrelated concurrent copies cannot poison capture eligibility.

A native capture error is not automatically a process fault. The recoverable path attributes a device drain to capture_rollback while admission remains open, then proves logical recurrent-state restoration. Only when both steps succeed may the runner disable graph capture, count capture_failure, and continue eagerly. Failed settlement, failed logical rollback, or an armed/unclassified capture guard leaving scope publishes sticky STOP first, uses error_recovery only for a post-STOP diagnostic drain, rejects eager continuation, and requires process restart. A later successful diagnostic drain never clears the quarantine.

Health repeats the policy at decode_runtime.accelerator_runtime. Its sibling decode_runtime.rocm_synchronization reports whether ROCm is active, telemetry availability, cleanup quarantine, total device/stream waits, waited nanoseconds, skipped barriers, and a fixed 23-reason array. cleanup_quarantined=true is a process-lifetime sticky device fault: further execution is rejected, possibly in-flight resources are retained rather than destroyed unsafely, and restart is required. Active ROCm telemetry unavailability is likewise fail-closed instead of being interpreted as a false quarantine value. The shared server admission gate latches either condition before adapter, training, import, or other backend mutation work can begin. The same snapshot makes backend_runtime unhealthy and quarantined, fails the backend_runtime_healthy readiness check, and returns HTTP 503. It is intentionally absent from /v1/config because it is live fault state, not policy. Prometheus exports kiln_rocm_cleanup_quarantined, kiln_rocm_synchronizations_total{reason,scope}, kiln_rocm_synchronization_wait_seconds_total{reason}, and kiln_rocm_synchronization_skipped_total{reason}, plus active, availability, and policy gauges. Interpret the quarantine gauge only when telemetry availability is one. These endpoints load atomics only and never synchronize the accelerator.

Configure the six fields under [accelerator]. Canonical environment names derive mechanically as KILN_ACCELERATOR_<FIELD>. Historical KILN_ROCM_GRAPHS, KILN_ROCM_GRAPH_CAPTURE, and KILN_ROCM_GRAPH_CACHE_MAX, plus the four old matmul force/disable names, are strict deprecated startup aliases, not hot runtime switches. See the complete accelerator configuration contract for mode semantics, validation, local A/B gates, and migration behavior.

vram: device and startup capacity resolution

Tape scope authority and inference isolation

The kt autograd tape is a required workload substrate, not a configuration feature. Kiln opens an internal thread-local training scope only around forward/backward work that must record gradients. Scope presence is the recorder’s sole activation authority: a request cannot open or close it, disable one link, or select a partially tape-backed workload. There is no TOML field, API property, CLI flag, or mechanically derived environment name for tape activation. An unavailable graph-preserving route makes the matching workloads[] member unsupported.

Ordinary inference never opens that scope and therefore retains forward-only fast paths. In particular, GDN chunkwise recurrence and CUDA’s weight-aware embedding lookup defer only while a training scope is actually active; neither consults a cached global tape default. While the scope is active, debug or performance tuning may select only an implementation whose backward stays connected to the same tape. It cannot suppress a recorder, sever the gradient graph, or silently change the optimizer update.

KILN_USE_TAPE_FORWARD, KILN_USE_TAPE_FLASH_ATTN, KILN_USE_TAPE_SDPA, KILN_USE_TAPE_LORA_ADD, KILN_USE_TAPE_GDN, KILN_USE_TAPE_GDN_CONV, KILN_USE_TAPE_GDN_QK_NORM, and KILN_USE_TAPE_GDN_GATED_NORM were removed without aliases or replacement fields. Delete them from service definitions. The portable source contract verifies ownership and inference isolation; it is not hardware qualification and does not claim accelerator-specific numerical, latency, memory, or stability evidence.

Frozen parameter ownership

Native SFT, GRPO, and OPD train LoRA A/B tensors and no base-model parameters. Embedding tables, base projection matrices, RMSNorm and gated-RMSNorm weights, GDN gate parameters, MTP projection weights, and loss-head transposes are saved constants rather than differentiable tape inputs. Backward operators return only the activation and LoRA gradients required upstream. They do not allocate, retain, deposit, or run matrix products for frozen-weight gradients; frozen fused normalization routes also omit dWeight outputs and atomics.

Both chunks of the split Q/gate projection retain the original full LoRA A/B IDs. Each chunk pads its B contribution to the full parameter shape before accumulation, and tape-aware reshapes preserve the post-split activation graph. A sliced base matrix or temporary B slice can never become an optimizer leaf. This ownership has no request, TOML, CLI, debug, or environment override. It removes frozen dWeight compute and storage by construction, but is not accelerator throughput evidence.

Exact LoRA gradient-set boundary

Before an optimizer mutates any parameter, moment, momentum, or step counter, the observed gradient tensor IDs must equal the configured trainable LoRA leaves. Every gradient must match its leaf’s shape, backward-compute dtype, and master device and contain only finite values. Missing or unknown IDs, metadata drift, NaN, and infinity reject the step; a finite all-zero gradient remains valid. There is no request, config, debug, or environment bypass.

CUDA, ROCm, and Vulkan use backend finite reducers. Metal currently synchronizes and copies each complete gradient to the host for the same stride-aware finite scan until a native Metal reducer is qualified. This is a correctness fallback, not a Metal large-batch throughput claim, and it cannot be disabled at the optimizer boundary.

Checkpoint reverse segments must return exactly the leaves in their layer range and the tape bridge produces one accumulated entry per leaf when distinct recorded inputs contribute to it. Every registered differentiable input must have a gradient before reduction, so one connected clone cannot hide a disconnected use of the same leaf. Split output-projection chunks assemble zero-padded contributions under the original full LoRA leaf ID rather than temporary slice IDs. A range with no configured LoRA leaves accepts only an empty gradient set. The checkpoint merge rejects duplicate leaf IDs across disjoint segments. Token-level GRPO validates each completion’s identity and metadata while accumulating, then performs one finite-value scan on the combined set immediately before optimizer mutation. SFT, GRPO, and OPD share this consumer contract.

DistillRefresh is a separate sequential workload, not an OPD alias. Its SFT knowledge phase and OPD behavior-recovery phase need separate exact phase plans; admission must prepare the precise SFT rows and reserve the larger of the two sequential working sets. Until one admission record pins all three facts, distill_refresh is always unsupported with reason distill_refresh is unavailable until admission pins separate exact SFT and OPD phase plans, prepares the exact SFT rows, and reserves the maximum sequential working set. Cheap teacher-alias validation and metadata pinning retain their established request-error ordering. Rejection still happens before seed derivation, checkpoint loading, remote/local teacher materialization, corpus scanning, memory preflight, or GPU reservation.

checkpoint_boundary_policy is the process-lifetime SFT boundary policy: recompute_mode is auto, enabled, or disabled; recompute_threshold_tokens is the inclusive automatic crossover; anchor_stride is a positive explicit stride or null for shape/cache-based selection; and cache_target_bytes is the startup-converted integral byte target. Attribute first-token latency

Set include_performance: true on a chat request to receive terminal metadata.performance. Batching-engine responses partition TTFT into actor_queue_ms (API enqueue to admission start), actor_admission_ms (slot preparation), and actor_prefill_wall_ms (admission completion to first sampled-token readiness), alongside accumulated model prefill_ms, decode_ms, TTFT, and total latency. resident_prefill_used is request-scoped route evidence: it is true only after a successful native multi-row resident-prefill forward included that request, false for batching requests that never entered the route, and null for direct paths. It is not inferred from process-global counters, and a mutation-free native decline remains false. Production currently advertises resident_prefill_enabled=false, so all batching requests must report resident_prefill_used=false. Non-batching paths return the actor fields as null. Both real-model streaming paths publish a performance object on the terminal chat chunk; explicit opt-in also emits a separate kiln.token_timing SSE object for each model token with a bounded path source, exact accepted token_id, plus producer-ready/delivered, handler-received, and response-queue times. The token ID remains observable when a special token decodes to an empty text fragment, without enabling logprobs or behavior capture. Direct streams retain the same request summary while leaving actor-only phases null and classifying otherwise unpartitioned gaps as unexplained. Batching-engine streams also propagate exact, invocation-owned gpu_lock_wait_ms and synchronization_ms candidates. ROCm sampled paged decode also reports its distinct post-transformer final-norm, LM-head, filtering, selection, and token-return tail as sampling_ms; behavior-logprob capture reports the same boundary across backends. readback_ms stays null because transfer is still nested inside that call and splitting it would add a second synchronization. Greedy or native fused-forward routes leave sampling null when no independent boundary exists. Graph, resize/trim, adapter, and training phases remain null until their owning runtime returns request-correlated timings; process-global counter deltas are never presented as per-request evidence. Mixed-load, development-soak, and endurance qualification receipts retain each phase as a measured-window millisecond total plus an observation count, so unsupported null remains distinct from a measured zero. A successful measured request without terminal phase metadata fails qualification, and broad actor and narrower backend totals must be ranked within their layer rather than summed as a critical path. The complete phase, overlap, reason-set, nullability, rolling-statistics, and Prometheus contract is documented in Latency Observability.

The ROCm mixed-load qualification runs an isolated fixed-seed sampled profile before its greedy measurement window: eight concurrent requests, 32 tokens each, temperature 0.7, top-p 0.9, top-k 40, and min-p 0.0. Dedicated sampled_profile_* metrics retain aggregate completion-window throughput, median per-request throughput, broad decode and sampled-tail costs, nullable readback population, and batch-width evidence. The driver drains the actor and captures a new health baseline before ordinary load, so the profile cannot contaminate established mixed-load counters. A pass requires sampled attribution for every request, no separately claimed readback timing, and proven multi-row decode.

Greedy measured requests bind prompt identity variant_invariant_fixed_output_v5. They request exactly 64 ascending six-digit integers while stating that server truncation before the target is expected. At roughly seven model tokens per integer, the target exceeds every 32-, 128-, and 256-token measured cap without the output-limit refusals caused by million- and 1,024-item measured requests. The prompt requires immediate sequence output, forbids explanation, refusal, summaries, and output-limit discussion, and uses only nonnumeric itemNN padding that is explicitly unrelated to output length. The separate unvalidated stalled socket retains a 1,024-integer fill target for its 4,096-token cap. Receipts record the prompt identity, response_oracle_target_integer_count = 64, slow_response_target_integer_count = 1024, and long_prefill_marker_role = "long-prefill". The diagnostic and acceptance paths therefore tokenize the same named long request for exact A/B configuration identity.

Slow-consumer containment uses a 256-token pressure peer, twice the ordinary response length. It dispatches that peer before opening the stalled socket and waits for that peer's first producer-ready token. Acceptance then requires additional producer-ready tokens during and after the request-attributed backpressure window. The typed schedule records pressure_peer_dispatch = "before_slow_start_after_first_token", proving continuity of an already-decoding request instead of comparing a queued peer with a pressure interval that began first.

The same ROCm gate records a typed Strix Halo thermal policy across server startup, warmup, both workload windows, drain, and teardown. A 250 ms k10temp/Tctl controller stops the server process group at 88 C, resumes it at 86 C, and fails closed at 97 C. Temperature, guard errors/trips, and complete pacing intervals are receipt metrics; cooling remains inside latency and throughput wall clocks and is attributed as host_thermal_pacing. The mixed-load client and server share a 180-second request bound. Receipts partition attributed ITL gaps into thermal-paced and non-thermal counts; only a reconciled thermal-only population may pass, and unexplained gaps must remain zero. Before SIGTERM, teardown disables new stops and releases any paced group while the hard limit stays active. After process exit, the runner requires eight consecutive 250 ms readings at or below 75 C, bounded to 180 seconds. Cooldown active/completed/timeout counts, duration, sample count, stable count, and post-exit peak are receipt metrics; a timeout or missing completion fails qualification. The local runner gives an interrupted driver a bounded cleanup window before hard containment and removes incomplete run evidence rather than leaving copied model shards behind.

Score prompt tokens

Set max_tokens to 0 or 1 and request prompt_logprobs from 0 through 256. The first result is null; each later position uses the preceding logits row and includes the observed prompt token plus top K, so its map has K or K+1 entries. K=0 returns only the observed token. Scores remain F32, extra observed tokens report full-vocabulary rank, and split UTF-8 display tokens use preceding actual prompt context. Invalid token IDs, decoding failures, non-finite values, and vocabulary-width mismatches fail closed. Text prompts default to add_special_tokens: true; -1 all-vocabulary requests are unsupported. The model ID must match the served base model, active LoRAs are rejected until adapter revision identity can be pinned, and the response is capped at 65,536 candidates. Scoring takes exclusive GPU admission, explicitly settles each projection chunk and final scorer state, and drains a timed-out worker before responding. Failed or panicked settlement quarantines the backend and retains admission. Every response carries a canonical teacher identity whose inference-contract v2 hash binds the complete startup-resolved streaming-prefill policy. Changing mode, threshold, any tile, or final-tile LM-head behavior changes the teacher revision and invalidates identity-bound logit caches and OPD resume bindings. The current path performs correctness-first O(TV) host readback rather than vLLM's selected-only O(TK) transfer path.

}

When both budgets are active, the first reached wins. The time clock starts at the first decode candidate, excluding queue and prefill, and Kiln checks it between tokens. A natural </think> wins if it arrives first. Otherwise Kiln feeds the forced close-tag tokens into model context and continues decoding the answer. Those tokens count toward max_tokens and completion usage. Budgets are inert unless the rendered prompt starts inside thinking.

  "closed": true,

  "thinking_time_ms": 742
}

Server SFT always normalizes omitted train_mtp to false and rejects explicit true before queue publication; the deferred MTP alignment phase remains offline-only until it participates in server GPU coordination, memory admission, cancellation, and settlement. A hybrid Vulkan server deliberately returns training_backend_unsupported before dataset admission: its serving weights use CPU-host handles, while the multi-GiB full-model resident Vulkan training path has not passed the production qualification gates. There is no environment bypass; use HF/TRL export/import until that substrate is proven. See the Native SFT Profile for update, precision, optimizer-state, checkpoint, and MTP semantics. Use the HF/TRL route for broader training: SFT and recorded-GRPO exports snapshot their canonical corpus, exact model/tokenizer/template provenance, optional split, and optional adapter into one private immutable registry, embed the task-aware pinned runner, and revalidate every byte before download. GRPO accepts exactly one provenance-complete inline group array or server-local canonical JSONL path. kiln train hf export-sft and export-grpo wrap creation, redirect-free streamed download, strict single-root archive validation, manifest verification, atomic no-clobber local publication, and default server cleanup; list and delete manage retained exports. kiln train hf import-peft verifies the completed local bundle before connecting, streams its deterministic corpus-free envelope through bounded memory, and accepts success only when HTTP 201, JSON, strong ETag, import digest, PEFT content revision, installed byte count, six-file count, task, and source identities match values derived locally; it retains the source bundle on every outcome. The raw PEFT import API accepts only the derived ten-file envelope, caps compressed/expanded/metadata resources, compares the complete current resident identity, validates every LoRA A/B shape, shares the adapter mutation barrier and strict disk quota, and stores a self-verifying kiln.hf-trl-import.v1 receipt before kernel-enforced no-replace publication. The versioned identity model, 256 MiB inline-body ceiling, 256-export registry cap, 2 GiB import-body ceiling, and lifecycle are documented in the HF/TRL Interoperability Contract.

config.optimizer is tagged by kind; omission selects Muon, and {"kind":"adam_w"} or {"kind":"muon"} selects that optimizer's defaults. Expanded forms may set beta1, beta2, eps, and weight_decay for AdamW or momentum, nesterov, ns_iters, and weight_decay for Muon. SGD accepts only {"kind":"sgd"}, and unknown fields are rejected. AdamW betas and Muon momentum must be finite in [0,1); epsilon must be finite and positive; both weight-decay values must be finite and non-negative; and Muon iterations must be in 1..=20. An explicit learning rate must remain finite and positive after F32 conversion. Omitted SFT rates resolve to 1e-3 for Muon and 1e-4 for AdamW/SGD; GRPO/OPD resolve 2e-3 and 1e-5, respectively. The cheap per-workload gate and resident optimizer tuple are checked before checkpoint or corpus materialization, at dequeue before memory reservation, and before device residency. This applies to direct training, the intent front door, every recipe step, judge/self-improve, DistillRefresh, and OPD-backed distillation. Cheap teacher-alias validation and metadata pinning may occur first; checkpoint loading, remote/local teacher materialization, corpus scanning, memory preflight, and GPU reservation occur only after the static workload check. Invalid optimizer kind, rank, or hyperparameters return structured training_invalid_request; unsupported base dtype, backend/device identity, Marlin-packed weights, serving-profile ownership, or authoritative tape/loss substrate return training_backend_unsupported. Neither changes route mid-run. A recipe descriptor is a static preview rather than a memory reservation; run submission preflights every step again before preparing any of them.

Every SFT source uses one row-admission contract. config.invalid_row_policy is fail by default; explicit skip queues only valid rows and records ordered kept/rejected SHA-256 identities under train_receipt.json → data.sft_ingestion. Server-local JSONL is revalidated against its submit-time manifest before GPU ownership. See SFT Ingestion, Invalid Rows, and Row Identity.

New exact checkpoints, train_receipt.json, and adapter_manifest.json persist the full validated base-weight shard manifest and kiln.execution-provenance.v1 process/runtime envelope. Exact resume first passes the current workload and resident tuple gates, then compares shard bytes and the canonical execution digest before GPU ownership. It separately validates the backend/device, optimizer kind and state, rank, concrete parameter/activation/gradient dtypes, immutable rounding mode, and checkpoint/tape/loss routes. Server training records only {"mode":"round_to_nearest"}. A legacy checkpoint recording stochastic rounding fails closed on precision mismatch before GPU ownership; Kiln does not discard its seed or continue under a different update rule. A changed native identity, newly Marlin-packed weight, unavailable authoritative route, aggregate-only checkpoint, or partial-runtime checkpoint is likewise not exact-resumable.

Queued resume admission fully validates the checkpoint manifest plus every declared artifact size and SHA-256, then retains only the checkpoint ID, a digest of that validated manifest (whose entries cover the artifact hashes), and the effective seed. Before memory reservation at dequeue, the worker fully reloads the checkpoint and requires both the recomputed identity and effective seed to match. This is revalidation, not a filesystem snapshot: the queue does not copy or pin checkpoint files, and it cannot eliminate a mutation race after the reload. Keep an exact checkpoint directory immutable for its entire use.

Native SFT checkpoint-boundary replay is also startup-authoritative. [training].recompute_checkpoint_boundaries defaults to auto, whose inclusive sequence threshold defaults to 8,192 tokens. checkpoint_boundary_anchor_stride defaults to auto and derives one positive stride from the admitted shape and the default 6 GiB checkpoint_boundary_cache_gb target; explicit positive strides bypass only that shape calculation. Canonical environment names derive mechanically as KILN_TRAINING_<FIELD>; the four historical unsectioned names are deprecated, parsed strictly, and must agree with a present canonical value. The same pure policy functions drive admission and execution, and no runtime path re-reads those names. Exact SFT checkpoints additionally bind the admitted backend loss route as sft_loss_route under kiln.training-checkpoint-planning.v4; prior SFT v3 checkpoints fail closed as planning drift. GRPO and OPD continue to retain every segment boundary and remain under kiln.training-checkpoint-planning.v3. A v2 checkpoint or any applicable policy change is planning drift and cannot resume exactly; the outer checkpoint envelope remains schema v1. Restart the server to change startup policy. See the configuration contract and checkpoint identity contract.

Training writes every artifact beneath a hidden staging root and captures the target’s starting content revision. Remote teachers use vLLM numeric-ID prompt_logprobs and must be launched with scripts/vllm_teacher.py. Registration probes K=1 and the advertised maximum K, verifies the complete tokenizer ID mapping against the student, and persists a canonical identity for exact base and optional static-adapter content, runtime, protocol, and scoring bounds. Every adapter Kiln produces can be graded by a registered or inline suite, compared head-to-head against any other adapter, or auto-evaluated the moment a training job finishes. Security note

Training data changes the active adapter

Kiln’s training endpoints are privileged: do not expose /v1/train/sft or /v1/train/grpo to untrusted inputs. Training validates request structure, not whether an example is semantically safe or desirable. Treat training data like code review input, and start with the README security model and Troubleshooting guide when hardening a deployment.

Response bodies

Response shapes

Inference responses follow OpenAI-compatible choices payloads. Training submissions return queued job metadata with a job_id, then /v1/train/status and the per-job /v1/train/status/{job_id} lookup report state, loss, adapter name, and any failure message.

Use the generated Inference API Schema for every inference request, response, nested object, optional field, and stream event rather than treating these workflow summaries or examples as a field contract.

For thinking responses, choices[].message.reasoning_content contains text before the natural or forced close, while content contains the final answer. Streaming uses the corresponding delta.reasoning_content and delta.content channels; raw thinking tags are not emitted on the separated path.
