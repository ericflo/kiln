Interpretation:
- A090's GDN recurrent prefill bucket is split mainly between Candle matmul
  prep (`k_t`, `ks_entry`, `kkt`, `qkt`, `q_s`) and Vulkan chunk scan. Chunk
  prep and state update are meaningful but smaller.
- The current 64-token path does not spend meaningful time in chunk slicing or
  final concatenation.
- Decode does not enter `single_token_backend_step`; it uses
  `single_token_fallback`, matching the full outer recurrent time. The active
  decode tensors are F32, while the existing backend-step gate only allows
  BF16.
- Next Vulkan decode experiment should test a Vulkan-only F32 recurrent-step
  route with an explicit rollback gate. That is separate from the A070/A091
  full-chunk prefill shape, which remains rejected.
