2026-05-09 A118: Fast Batched Linear-State Scatter

Scope:
- Shared model scheduler/state change, measured on Vulkan live batch 3.
- Added `LinearAttentionState::scatter_batch_rows_replace`, which narrows each
  row out of the batch state once and assigns the resulting tensors directly to
  scheduler-owned row states.
- `LinearAttentionState::scatter_batch_rows` remains unchanged for
  pointer-stable restore/copy semantics.
- `ModelRunner::decode_next_tokens_paged_contiguous_batch_greedy` now uses the
  replace scatter only for the already-batched path.
- Rollback:
  KILN_DISABLE_FAST_BATCHED_LINEAR_STATE_SCATTER=1.

Why:
- The old batched decode scatter path did:
  1. split every row with `narrow(...).contiguous()`;
  2. call `restore_from`, which copied each recurrent and conv tensor again.
- For Qwen3.5-4B live batch 3, that is an avoidable extra copy over all GDN
  layers after every batched decode step.
- Batch-size > 1 CUDA graph replay is not used here, so the scheduler-owned
  row states do not need the old destination tensor handles preserved.

Wall-time evidence:
- Pair 1:
  - Candidate fast scatter: 17.459836529000313s.
  - Rollback copy scatter: 18.72559554698819s.
  - Candidate win: 7.25%.
- Reversed pair:
  - Rollback copy scatter: 18.83306049600651s.
  - Candidate fast scatter: 17.982479065991356s.
  - Candidate win: 4.73%.
- Aggregate:
  - Candidate average: 17.721157797495835s.
  - Rollback average: 18.77932802149735s.
  - Candidate speedup: 5.97%.

Decision:
- Accepted.
- This reduces scheduler-side state movement without changing GDN math,
  Vulkan kernels, CUDA kernels, or Metal kernels.
- Batch-1 decode remains on the existing path; pointer-stable restore remains
  available through `scatter_batch_rows`.
