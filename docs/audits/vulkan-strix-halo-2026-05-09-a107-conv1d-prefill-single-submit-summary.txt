A107 Accept Vulkan Conv1d Prefill Cached Single Submit

Date: 2026-05-09
Target: Qwen3.5-4B, AMD Radeon 8060S Graphics (RADV_STRIX_HALO), Vulkan backend.

Change:
- Vulkan-only multi-token causal conv1d prefill now uses a cached immutable f32
  weight buffer and folds x/state uploads, the output dispatch, the state
  advance dispatch, and out/state readbacks into one command buffer and one
  queue submit.
- `crates/kiln-model/src/backend/vulkan.rs` keeps the previous tensor-weight
  prefill route as a rollback path.
- Rollback env:
  `KILN_DISABLE_VULKAN_CONV1D_PREFILL_SINGLE_SUBMIT=1`.
- Broader conv prefill rollback remains:
  `KILN_DISABLE_VULKAN_FUSED_CONV1D_PREFILL=1`.
- CUDA and Metal source paths were untouched.

Why this differs from rejected A088/A089:
- A088/A089 only grouped copy submissions and regressed.
- A107 also removes per-layer weight upload from the production path and folds
  compute plus readback boundaries, so it changes the host/queue boundary rather
  than only batching transfer commands.

- Seed `129`: candidate `964.346ms` / `79.058ms` / `88.162ms`; rollback

- Three-pair average: candidate `968.640ms` prefill / `78.652ms` mean ITL /

- Approximate 64 prompt + 8 ITL total: candidate `1597.859ms`; rollback
  `1624.502ms`.

Verdict:
- Keep.
- The win is smaller than A105 but same-token across all pairs, improves
  aggregate latency by about `26.6ms` (`1.6%`) on this short serial harness,
  and has a narrow rollback guard.
- Do not treat this as evidence that transfer-only conv batching is good; the
  accepted shape is cached-weight plus one-submit transfer/compute/readback.
