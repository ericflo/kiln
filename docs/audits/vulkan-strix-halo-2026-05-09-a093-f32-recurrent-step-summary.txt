Verdict:
- Keep. This is a narrow Vulkan-only decode correctness/performance route:
  active F32 decode tensors now run the existing Vulkan recurrent-step kernel
  instead of the CPU-style single-token fallback.
- Next serial decode work should use a fresh post-A093 profile because GDN
  recurrent is no longer the same fallback-shaped bucket.
- Next prefill recurrent work should target `chunk_scan`, `chunk_prep`,
  `matmul_prep`, or broader adjacent-stage residency/fusion, not
  `slice_inputs` or `cat_out`.
