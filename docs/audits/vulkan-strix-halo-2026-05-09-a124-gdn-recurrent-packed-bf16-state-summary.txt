A124 GDN recurrent packed BF16 state candidate summary

Date: 2026-05-09
Host: Strix Halo / RADV STRIX_HALO
Base commit: 83e5ab03 Profile Vulkan after BF16 inference state
Disposition: rejected; source change removed after measurement

Purpose
-------

Test whether packing Vulkan GDN recurrent BF16 state as two BF16 values per
u32 in a column-major `[B,H,dv,ceil(dk/2)]` layout improves live batch-3
decode by reducing recurrent state upload/readback size. The candidate was
Vulkan-only and had a rollback flag:
`KILN_DISABLE_VULKAN_GDN_RECURRENT_BF16_STATE_PACKING=1`.

Candidate shape
---------------

- Added a parallel recurrent shader variant for BF16 mutable state.
- Kept q/k/v/beta/g uploads as f32 bytes.
- Packed recurrent state column-major by output column so each workgroup owned
  one `(b,h,d)` column and wrote whole packed words.
- Forced device-local state for the packed path.
- Unpacked readback into the normal row-major BF16 `[B,H,dk,dv]` tensor.
- Added focused BF16 parallel-reduce parity coverage while the candidate was
  present.

Correctness
-----------

- All four arms confirmed GPU routing:
  `Mode: GPU inference`, Vulkan available, RADV STRIX_HALO selected, and live
  greedy decode batcher backend `vulkan`.
- All four arms returned `8/8` HTTP 200.
- All four arms emitted empty reasoning streams.
- Every visible response exactly matched:
  `"eight, nine, ten, eleven, twelve, thirteen, fourteen, fifteen,"`.
- Every measured arm had identical decode-batcher metrics: `128` generated
  tokens, `120` submitted jobs, `41` worker batches, `120` batcher rows, max
  batch `3`, and no request or batcher errors.

Performance
-----------

- Pair 1, candidate first: candidate `13.626650s`, rollback `13.731983s`,
  candidate delta `+0.767%`.
- Pair 2, rollback first: rollback `13.885340s`, candidate `16.862532s`,
  candidate delta `-17.656%`.
- Two-pair averages: candidate `15.244591s`, rollback `13.808662s`,
  candidate delta `-10.399%`.

Interpretation
--------------

- Correctness was clean, including visible text and real template-config
  handling.
- The candidate did not earn its complexity. Any state-transfer savings were
  outweighed by CPU-side packing/unpacking, shader bit packing, layout
  conversion, or run-to-run variance.
- Source changes were removed after measurement. Current source has no A124
  runtime changes, and CUDA/Metal source paths remain untouched.
- Do not revive this direct packed-state upload/readback approach without a
  broader resident-state design that avoids per-token CPU packing and
  unpacking.
