A112 rejected candidate: Vulkan MLP gate/up packed-BF16 row-triple at batch 3

Scope
-----
- Temporarily added `mlp_gate_up_decode_batched_rows3_bf16w.comp`.
- Routed packed-BF16 MLP gate/up decode with `batch == 3` through the
  row-triple shader.
- Temporary rollback env:
  `KILN_DISABLE_VULKAN_MLP_BF16_GATE_UP_ROWS3=1`.
- CUDA and Metal source paths were not changed.
- Final source was reverted after measurement; only this audit trail remains.

Why
---
- Metal E466 accepted an exact-batch-3 MLP gate/up row-triple path with both
  synthetic and live endpoint wins.
- Vulkan MLP fused remains a major decode bucket, so this was a narrower and
  more relevant follow-up after A111 rejected generic linear row-triple.

Validation While Present
------------------------
- `cargo fmt --check`
- `git diff --check`
- `cargo check -p kiln-vulkan-kernel`
- Focused Vulkan parity:
  `cargo test -p kiln-vulkan-kernel --test gdn_parity mlp_decode_bf16_packed_weights_match_cpu_reference -- --nocapture`
  covering batch 3 through the existing focused test.
- Focused rollback parity with
  `KILN_DISABLE_VULKAN_MLP_BF16_GATE_UP_ROWS3=1`.
- Full Vulkan kernel parity: `34 passed`.
- `cargo check -p kiln-model --features vulkan`
- `cargo check -p kiln-server --features vulkan --bin kiln --bin kiln-bench`
- `cargo build --release -p kiln-server --bin kiln --features vulkan`

Live A/B
--------
- Server env for valid probes:
  `KILN_MODEL_PATH=Qwen3.5-4B KILN_DECODE_BATCH_WAIT_US=5000`
- Rollback env additionally:
  `KILN_DISABLE_VULKAN_MLP_BF16_GATE_UP_ROWS3=1`
- Old live decode-batcher path was used; `KILN_BATCHING_ENGINE=1` was not used.

Short exact batch-3 probe:
- Candidate `1.581423s`; rollback `1.579940s`.
- Both arms: `requests_ok=3`, `tokens_generated=9`, `jobs_submitted=6`,
  `worker_batches=3`, `batcher_rows=6`, `max_batch_after=3`,
  `jobs_failed=0`.
- Visible outputs matched: `"The sequence you"` for all three streams.

Metal-matched four-stream `max_tokens=8` probe:
- Uncapped run reached max batch 4, so it was not pure batch-3 evidence.
- Rollback `4.928977s`; candidate `4.998365s`.
- Both arms had `requests_ok=4`, `tokens_generated=32`,
  `jobs_submitted=28`, `batcher_rows=28`, `max_batch_after=4`.
- All visible outputs matched:
  `"eight, nine, ten, eleven,"`.

Capped four-stream `max_tokens=8` probe:
- Added `KILN_DECODE_BATCH_MAX=3` to force the intended max batch 3 shape.
- Rollback `4.950162s`; candidate `5.103933s`.
- Both arms had `requests_ok=4`, `tokens_generated=32`,
  `jobs_submitted=28`, `batcher_rows=28`, `max_batch_after=3`.
- Worker batches differed slightly (`11` rollback, `10` candidate), but the
  candidate still lost wall time.
- All visible outputs matched:
  `"eight, nine, ten, eleven,"`.

Verdict
-------
- Rejected and reverted.
- The candidate was correct, but it failed to beat rollback on the exact
  short batch-3 probe and regressed the longer capped max-batch-3 probe.
- Do not direct-port Metal E466's MLP gate/up row-triple shape to Vulkan
  without a different Vulkan-specific tile or scheduling hypothesis.
