A073: label Vulkan standard full-attention prefill fallback stages

Date: 2026-05-09
Target: Qwen3.5-4B, Vulkan backend, AMD Radeon 8060S Graphics (RADV_STRIX_HALO)

Purpose
-------

Recent Metal E412/E413 re-enabled full-SDPA prefill and showed a large Metal
prefill win. A071 did not expose the equivalent standard full-attention prefill
fallback internals on Vulkan: full-attention prefill printed QKV, layout, K/V,
and decode stages, but the standard fallback attention math and output
projection were unlabelled.

This change adds profile-only labels around the standard full-attention
fallback path:

- `prefill_gqa_expand`
- `prefill_kv_contiguous`
- `prefill_scores`
- `prefill_mask`
- `prefill_softmax`
- `prefill_weighted_sum`
- `prefill_output_layout`
- `attn_gate`
- `o_proj`

When `KILN_PROFILE_FULL_ATTN_STAGES` is not set, these wrappers return
immediately and do not synchronize.

Validation
----------

- `cargo fmt --check`
- `git diff --check`
- `cargo check -p kiln-model`
- `cargo check -p kiln-model --features vulkan`
- `cargo build --release -p kiln-server --bin kiln-bench --features vulkan`

Cross-feature checks attempted:

- `cargo check -p kiln-model --features cuda` is blocked on this host because
  `nvcc` is unavailable.
- `cargo check -p kiln-model --features metal` is blocked on this host because
  `objc2` only compiles for Apple targets.

Interpretation
--------------

The new labels show the Vulkan standard prefill attention math is not the
dominant hidden bucket for the 64-token prompt shape. The main full-attention
prefill cost is QKV projection (`183.112 ms`) and then O projection
(`46.860 ms`). The SDPA-like fallback internals, excluding gate and O
projection, total about `14.429 ms` across all 8 full-attention layers:

- scores: `6.368 ms`
- mask: `1.446 ms`
- softmax: `2.281 ms`
- weighted sum: `3.178 ms`
- GQA expansion: `0.640 ms`
- output layout: `0.516 ms`

That is below MLP fused (`879.833 ms`) and the major GDN prefill buckets. The
Metal E412 full-SDPA lesson is useful as a profiling question, but it does not
point to the next Vulkan implementation target unless longer prompts show a
larger standard-attention bucket.

Verdict
-------

Keep the profile labels. They close a full-attention prefill blind spot with no
runtime behavior change when profiling is disabled.

Do not prioritize a Vulkan full-SDPA prefill port for the current 64-token
Strix Halo shape. The next Vulkan work should stay focused on MLP
boundary/data movement and GDN in-proj/recurrent/conv residency or transfer
shape.
