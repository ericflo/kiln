A105: Vulkan MLP chained transfer submit

Status: accepted
Date: 2026-05-09

Change:
- Added a default-enabled Vulkan MLP decode path that folds input upload,
  chained gate/up dispatch, down-projection dispatch, and output copy/readback
  into one command buffer and one queue submit.
- The path is only active when the existing MLP chained dispatch path is active.
- Rollback: `KILN_DISABLE_VULKAN_MLP_CHAINED_TRANSFER_SUBMIT=1`.
- Broader rollback: `KILN_DISABLE_VULKAN_MLP_CHAINED_DISPATCH=1`.
- CUDA and Metal source paths are untouched.

  passed.
- `git diff --check` passed.
- `cargo check -p kiln-vulkan-kernel` passed.
- Focused MLP parity passed in both candidate and rollback modes:
  `cargo test -p kiln-vulkan-kernel --test gdn_parity mlp_decode -- --nocapture`
  reported 4 passed in each mode.
- Full Vulkan kernel parity passed:
  `cargo test -p kiln-vulkan-kernel --test gdn_parity -- --nocapture`
  reported 34 passed.

- Release Vulkan bench and server builds passed with pre-existing warnings:

Verdict:
- Keep.
- This is a narrow Vulkan-only command-boundary reduction. It removes two
  submit/wait boundaries around the already-kept MLP chained compute path and
  produces a stable same-token win across the three-pair no-profile bench.
- The rollback guard is specific enough to disable only the new transfer/submit
  folding while preserving the older chained compute dispatch path for
  diagnosis.
