A070: Vulkan GDN full-chunk shader parity fix, default enable rejected

Date: 2026-05-09
Target: Qwen3.5-4B, Vulkan backend, AMD Radeon 8060S Graphics (RADV STRIX_HALO)

Candidate
---------

The existing `gdn_full_chunk_forward.comp` shader was embedded and prewarmed,
but the Vulkan backend kept `supports_gdn_full_chunk_forward()` hard-disabled
because the shader had not been validated against the split chunk path.

Inspection found the shader was stale: it did not implement the same
prep/scan/state-update contract as the current split path and did not write the
updated recurrent state. A corrected version was implemented and covered by a
new parity test against the existing Vulkan split path:

- `gdn_chunk_prep`
- `gdn_chunk_scan`
- Rust-side `p_last * state + k_t @ w_weighted` state update

Default enable was tested and rejected. The final committed route keeps the
shader opt-in only:

- `KILN_ENABLE_VULKAN_GDN_FULL_CHUNK_FORWARD=1`

Verdict
-------

Keep the shader correctness/parity fix and the opt-in tuning gate. Reject
default enable on Strix Halo: candidate prefill was 2216.728457 ms versus
rollback 2138.199230 ms.

The result confirms that correctness alone is not enough here. This fused
shader serializes too much work inside one workgroup and loses to the existing
split prep/scan path despite reducing CPU boundary crossings. Future work
should not enable this shape by default without changing the parallelization
strategy.

CUDA and Metal source paths were not changed.
