# Hypothesis: h1-r16-6ep

## Family
H1 — epoch curve, first ablation

## Claim
Proven recipe (rank=16, alpha=32, lr=1e-4, 6 epochs, samples_per_prompt=1,
max_tokens=128, top_k=8) will lift `entity_recall` by ≥5pp (0.676 → ≥0.726)
and composite by ≥2.5pp (0.728 → ≥0.753). This is a free-form capability
so the 87% skip rate from JSON-schema (not the 97% from symbol-extraction)
applies; effective steps should land around 20 of 156 nominal.

## Mechanism
The 4B's entity-drop pattern (missing file paths, function names, errors)
is exactly the kind of "student samples in a slightly off-distribution
region the teacher would have visited" that OPD bridges. At each
sampled position the teacher's logprob distribution will have higher
mass on the entity tokens; reverse-KL pulls the student toward including
them.

## Falsification plan
- If composite Δ < +1pp: H1 didn't transfer to this capability shape.
  Pivot to H2 (broader prompts) or H6 (off-policy SFT cold-start).
- If composite Δ in [+1pp, +2.5pp]: under-claim but real. Iter 2 = 9 epochs.
- If composite Δ ≥ +2.5pp: claim confirmed. Iter 2 = either H1 12 epochs or
  triangulation with H3 (samples_per_prompt=2).
- If entity_grounding regresses by >1pp (0.96 → <0.95): training is causing
  the model to invent entities. Pivot to H7 (Stable-OPD mix).

## Verdict
(filled after eval)

Verdict: ? Inconclusive — composite +3.17pp (0.8098 → 0.8415, meets ≥+2.5pp
claim) but the target sub-score `entity_recall` was FLAT (-0.39pp vs claimed
≥+5pp). The composite lift came from length_band (+29.69pp) which we
weren't targeting; decision_retention regressed -10.84pp (saturated at
baseline so any movement is loss). The adapter learned "compress more"
rather than "include more entities" — a confound, not the intended
mechanism. 95% skip rate (8 effective steps of 156 nominal) means the
LoRA only saw a sliver of the prompt set. Pivot iter 2 to H8 (prompt
pruning of length-already-compliant prompts) so gradient lands on
entity-recall failures, not on length-band-easy ones.

Note: rubric was rebalanced mid-iter — original decision_retention pattern
was too narrow (only verb forms, no nouns like "Decision:" or imperatives
like "Revert"). Fixed in commit (pending). Both baseline and iter 1 were
re-scored with the corrected rubric.
