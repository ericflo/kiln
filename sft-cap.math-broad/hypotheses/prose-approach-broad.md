# Hypothesis: prose-approach-broad

(T-family per §4 of SKILL.md. Iter 1 default — must be a T-family ablation
to honour the skill's "teach by words, test by deed" asymmetry.)

## Claim

64 word-situation examples in which the user asks how to *approach* a
real-world scenario that has a mathematical structure, and the assistant
explains the conceptual approach in prose (no numbers, no symbolic
manipulation, no final answers), will raise the math oracle's broad
accuracy by lifting the model's *routing* into mathematical concepts —
not its arithmetic primitives.

## Mechanism

A 4B model already has fluent arithmetic, algebraic, and calculus
*primitives* — what it lacks is reliable *routing* into them when a
question is posed. When asked "what is the volume of a cone with radius
3 and height 5", a model can either (a) recognise this as cone-volume,
recall πr²h/3, and compute, or (b) hallucinate, drift, or fail to
identify the relevant concept. Path (a) is a frame-recognition problem,
not an arithmetic problem. Prose supervision that *describes when and
how a mathematician would reach for a particular concept* re-shapes the
latent priors that govern frame recognition — without ever exercising
the symbolic surface form. The Qwen3 architecture also has a
`reasoning_content` channel; prose supervision in the assistant turn
should bias the model toward longer, more reliable concept-naming
during inference reasoning. We test pure-prose first because if it
works, every subsequent ablation can layer on it; if it fails, the
falsification plan below already specifies the form-anchor fix.

## Dataset shape

- Size: 64 examples
- Modality of supervision: pure prose. Assistant turns contain zero
  numerical answers, zero equations, zero symbolic manipulation, zero
  `<think>` blocks (we want the model to learn the *content* of routing,
  not the *form* of thinking). User turns are short prose situations.
- Distribution by math domain (rough; varies framing widely within each):
  - 12 arithmetic / mental-math / estimation contexts (everyday quantities)
  - 10 geometric / spatial contexts (area, volume, tiling, angles)
  - 10 algebraic / unknown-quantity contexts (puzzles, missing-info)
  - 8 trig / periodic contexts (waves, shadows, oscillation)
  -  8 systems-of-equations contexts (constraints, mixtures, ratios)
  -  8 calculus / rate-of-change contexts (filling, draining, growth)
  -  8 ODE-shaped contexts (population, compound interest, decay)
- Surface form held OUT (likely or possibly used by the eval):
  - No worked numerical examples
  - No equations written out
  - No "Answer: <number>" sentinels
  - No multiple-choice formatting
  - No problems that match the *style* of competition math
- System prompt: none (per §3 Phase 2 rule 1).

## Construction recipe

Hand-drafted by the agent. Each example follows a 3-part template:

  USER:  "[Real-world situation framing, 1-3 sentences]. How would
          [a baker / a builder / a navigator / an engineer / a forester]
          think about this kind of problem?"

  ASSISTANT: "[2-5 sentences of conceptual prose. Names the relevant
              mathematical idea by its everyday-language equivalent
              ('how things scale', 'pieces that fit together',
              'changing rates', 'unknowns that must balance'). Describes
              the *steps of reasoning* a competent practitioner would
              take. Never produces numbers. Never writes equations.]"

Variety is generated by varying:
  - the profession framing the question
  - the everyday-language label for the math concept
  - the level of abstraction (sometimes very concrete, sometimes
    explicitly generalising)
  - sentence structure / voice

## Risk

The most likely failure mode is **answer-form drift**: the model learns
that "the right answer is prose" and starts producing prose for math
problems the eval scores by exact-match on a number. This would manifest
as Δ < 0 (worse than baseline). Per §11 the iter-2 fix is to add 10-20%
short-answer anchor examples — same conceptual content but with the
user asking for a specific numerical instance and the assistant
producing a terminal number.

A subtler failure mode is **no transfer**: the model just absorbs the
style and the broad routing is unchanged. This would manifest as
Δ ≈ 0 (within noise). Per the §4 taxonomy the next step is then to try
a different shape of T-family supervision — e.g., assistant turns that
*name the mistake* a novice would make, rather than the right approach,
or meta-questions like "what kind of math problem is this?"

A "fake win" risk: the eval contains some prose-style problems (e.g.,
word problems) and the model gets better at THOSE specifically rather
than broadly. This would not be visible in a single-number score.
Triangulation (iter 3+) will probe this.

## Falsification plan (committed BEFORE seeing the score)

Let MAD be the median absolute deviation across logged ablations
(post-iter-3 only meaningful; before then use a placeholder threshold
of 0.04 absolute).

- If Δ ≥ +0.05 vs baseline AND anchor unchanged: KEEP. Next iter is
  a refinement (`prose-approach-broad-paraphrased`) with the same recipe
  but explicitly more diverse framings (formal/casual/terse/technical).
- If Δ in [+0.02, +0.05): borderline KEEP, but next iter is a shuffle
  confirmation (`prose-approach-broad-shuffle1`) to rule out
  example-order noise per §5.
- If Δ in [-0.02, +0.02): within noise. Discard. Next iter pivots to
  triangulation — a *control* ablation with numeric worked examples on
  the same domains, testing whether prose was doing causal work.
- If Δ in [-MAD, -0.02): probable answer-form drift (§11). Discard.
  Next iter is `prose-approach-broad-anchored`: same dataset + 12
  short-answer anchor examples appended (10% of corpus).
- If Δ < -MAD: severe regression. Discard. Next iter is
  `prose-approach-broad-half-anchored`: keep only 32 of the 64 prose
  examples + 16 short-answer anchors, training mass split. If THAT
  still regresses, the prose route is dead for this base model and we
  retire the T-family entirely.
- Anchor regression > 2× MAD on the general-competence eval: regardless
  of math score, flag as "Pyrrhic". Next iter uses lower lora_rank
  (rank 2) on the same dataset to reduce stylistic clobber.
